# VibeUI Outreach Agents

Отдельный сервис автоматизации работы с блогерами. Он не импортирует код основного сайта и не хранит секреты в репозитории.

## Что уже работает

- PostgreSQL-схема для кандидатов, очереди, запусков, аудита и управляющих флагов;
- надёжная очередь с идемпотентностью, повторными попытками и `SKIP LOCKED`;
- AI-оценка кандидата по шкале из плана со структурированным результатом;
- discovery: YouTube Data API, Rutube, Хабр, Dev.to (открытые API без ключей), Telegram (обход по ссылкам и поиск через аккаунт), VK; склейка блогера между площадками;
- планировщик в worker (раз в 30 мин, `src/scheduler.ts`): сначала оценка уже найденных, новый поиск — только если запас кандидатов меньше 3 дней писем и не исчерпан дневной лимит (меняется в админке, «Поиск»); запросы по площадкам — `discovery` в policy;
- единый порог оценки в БД (`agent_control.minimum_score`, по умолчанию 65), меняется в админке с пересчётом допуска;
- безопасный JSON-импорт кандидатов, публикаций и подтверждённых business-контактов;
- персонализация по одной подтверждённой публикации с проверкой URL-источников;
- детерминированная проверка допуска к первому контакту;
- worker с журналом запусков и реакцией на аварийную остановку;
- отправка через Resend с ключами идемпотентности и проверенными webhook-событиями;
- классификация ответов и немедленный глобальный `do_not_contact` при отказе или отписке;
- защищённая Basic Auth админка с блогерами, сообщениями, очередью, уведомлениями, журналом и emergency stop;
- учёт токенов и стоимости по агенту и кампании, автоматическая остановка по бюджету;
- реферальная ссылка из закрытого API VibeUI (`POST /api/internal/invites`) в каждом первом письме;
- ежедневная сверка блогеров со ссылкой (`GET /api/internal/invites?creatorId=`): принял приглашение — запись в `partners`, статус `partner_created`, цифры в `referral_metrics`;
- отправка через Gmail и сбор ответов, уведомления в Telegram;
- мониторинг публикаций: ссылка, disclosure и обязательный `erid` для RU;
- безопасные значения по умолчанию: рассылка отключена, первый контакт требует человека.

Отправка реализована, но **заблокирована по умолчанию** одновременно policy-файлом, dry-run статусом кампании и паузой в БД. Для реальной отправки нужны подтверждённый домен Resend, ключи и явное включение всех трёх уровней после проверки черновиков.

## Запуск

Требуются Node.js 20+, PostgreSQL и API-ключ OpenAI.

Для тестов поддерживается OpenRouter через OpenAI-compatible Chat Completions:

```env
OPENROUTER_API_KEY=...
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENAI_SCORING_MODEL=openai/gpt-6-luna
OPENAI_GENERATION_MODEL=openai/gpt-6-luna
HARD_MODEL_BUDGET_USD=0.80
```

При наличии `OPENROUTER_API_KEY` SDK автоматически переключается на OpenRouter и отключает экспорт OpenAI traces. `HARD_MODEL_BUDGET_USD` — независимый локальный предохранитель; после его достижения новые модельные операции блокируются в БД.

```bash
cd agents
cp .env.example .env
# загрузить переменные из .env удобным для вашей ОС способом
npm install
npm run migrate
npm run admin
# в отдельном процессе:
npm run worker
```

Исследовательский импорт YouTube:

```bash
npm run discover -- youtube ru "вайбкодинг" 25
npm run discover -- youtube en "vibe coding" 25
```

Импорт собственной проверенной базы и подготовка черновиков:

```bash
npm run import -- examples/creators.example.json
npm run prepare-drafts
```

Админка по умолчанию доступна только локально: `http://127.0.0.1:4310`. Перед запуском задайте `ADMIN_PASSWORD` длиной не менее 16 символов. Не открывайте этот порт напрямую в интернет; для удалённого доступа используйте TLS reverse proxy и дополнительный сетевой контроль.

## Защитная модель

Политика находится в `policy/default-policy.json`. Изменение JSON не снимает флаг emergency stop в базе. Включение outreach в политике также недостаточно: администратор должен отдельно снять паузу. Автоматическая отправка первого письма не реализована намеренно — в политике зафиксировано ручное одобрение.
