### Чтобы включить Telegram-поиск
1. my.telegram.org → API development tools → `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` в `/etc/vibeui-agents/agents.env`.
2. На сервере (или локально): `npm run telegram-login` → телефон, код → строка `TELEGRAM_SESSION=...` в env.
3. Рестарт worker. Без этих переменных источник просто не попадает в ротацию.

## 2026-10-09 — площадки кроме YouTube: диагноз

- Поиск по расписанию в репо нет: все `discover` запускаются руками из CLI (`src/cli.ts`).
- YouTube — поиск по ключевым словам через Data API, единственная площадка с поиском.

- VK (`discovery/vk.ts`) — тоже обход по ссылкам, нужен `VK_SERVICE_TOKEN` (нет в `.env.example`). Поиск сообществ
  сервисным токеном недоступен.
- Состояние прода (что в env, сколько профилей по площадкам) не проверено: read-only SSH заблокирован гардом.

## 2026-10-09 — партнёры: связка агент ↔ сайт

### Как устроено (проверено по коду)
- Партнёр на сайте = пользователь, принявший приглашение (`partner_invite.claimed_by`).
  Принятие — `claimInvite` (`lib/partners.ts`): реф-код + 30 дней Pro.
- Агент создаёт приглашение: `POST /api/internal/invites` (`app/api/internal/invites/route.ts`),
  Bearer `AGENTS_API_KEY`. Слово `for_<ник>` = реф-код и промокод. Тег в имени `[agent:<creatorId>]`.
- `GET /api/internal/invites` — общая воронка по всем агентским приглашениям (админка агента).
- База общая для `.ru` и `.club`.

- Таблицы агента `partners`, `publications`, `referral_metrics` остаются (их читают админка и монитор публикаций).
  Таблица `partner_offers` остаётся в БД, из кода убрана.
