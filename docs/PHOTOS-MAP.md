# Карта демо-фотографий

Что на каком файле в `public/demo/`. Составлено просмотром всех кадров —
чтобы подбирать картинку под товар по списку, а не открывать 142 файла заново.

Правило подключения: путь к файлу живёт только в `meta.preview.props`
(демо-данные каталога). В сам блок демо-пути не попадают — установленный
компонент не должен ссылаться на файлы VibeUI.

Как устроен слот. У item'а появляется проп — `image` для кадра, `avatarImage`
для лица — пустой по умолчанию. Внутри рамки стоит `<img>`, а прежняя цветная
подложка уезжает на `[data-part="…"][data-empty="true"]` и рисуется, только
когда фотографии нет: item обязан оставаться полноценным без единого внешнего
файла. Рамка получает `position:relative` и `overflow:hidden`, изображение —
`position:absolute; inset:0; object-fit:cover`.

Три ловушки, на которых это ломалось:

- **подложка инлайном.** В `blog-001` и `blog-003` градиент задавался прямо в
  разметке по оттенку рубрики и ложился поверх фотографии. Лечится переносом
  градиента в CSS, в разметке остаётся только переменная оттенка;
- **слот вне цикла.** Аватар автора или обложка одной статьи не имеют
  переменной цикла — им нужен проп блока, а не поле элемента списка;
- **не всякая заглушка — фото.** `thumb` у переключателя, `frame` у поля
  ввода, `banner` у текстовой плашки, `frame` у сцены анимации и скелетоны
  загрузки держат пропорцию или залиты градиентом, но картинка в них была бы
  ошибкой.

Аватары подбираются по полу имени: иначе на карточке «Алексей Громов»
оказывается женское лицо.
