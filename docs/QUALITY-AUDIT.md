# Аудит качества каталога

Дата: 2026-09-12. Полный проход по всем 1584 items (122 категории: компоненты,
блоки, анимации) в два слоя:

1. **Статический аудит** — скрипт по коду и metadata каждого item:
   собственная палитра `--vibeui-<name>-*`, `light-dark()`,
   `prefers-reduced-motion` при наличии анимации, `alt` у картинок,
   фокус-стили, размер файла, inline-стили, сетевые вызовы, импорты кода
   приложения, `any`, полнота metadata (description, tags, ai.*, i18n.en).
2. **Визуальный проход** — категория открыта в браузере, превью каждого
   item просмотрено глазами. Критерии: композиция и выравнивание, контраст,
   реалистичность демо-контента, современность приёмов, отличимость items
   внутри категории, поведение в узкой карточке каталога. **Охват глазами:
   ~104 из 122 категорий** — все 74 компонента, 23/34 блока (все визуально
   различные), 7/18 анимаций (все визуально различные). Оставшиеся ~18 —
   малые 3-item категории того же дизайн-языка, разобраны по `registry.json`.
   В середине dev-сервер один раз деградировал (OOM, 6.3 ГБ на слабой
   машине i5-6200U); после перезапуска проход продолжен.

Оценки категорий: ✦ отлично · ✓ хорошо · ~ средне · ✗ слабо.

---

## Слой 1. Статический аудит: 63 items с флагами из 1584

Метаданные чистые у всех: description, tags, ai.summary/preserve/adapt,
i18n.en присутствуют везде (заслуга `meta:validate`). Флаги по коду:

### Нарушения правил реестра — ПРОВЕРЕНО, все ложные

Регэкс-аудит поднял 6 «критичных» флагов. После ручной проверки исходников
**ни один не подтвердился**:

| Флаг | Реальность |
|---|---|
| codeblock-002 «импорт `@/…`» | строка `import {Button} from "@/…"` — демо-код *внутри* блока кода, не реальный импорт |
| codeblock-006/008/016 «`fetch`» | `fetch(...)` — текст в отображаемом листинге, не вызов |
| combobox-023 `dangerouslySetInnerHTML` | слово встречается **в комментарии**: «…без dangerouslySetInnerHTML». Компонент как раз его избегает (нарезка + `<mark>`) |
| hero-001 «нет палитры» | палитра есть, просто в namespace `--vibeui-hero-*` (общий для категории hero), а не `--vibeui-hero-001-*`. Слишком строгая проверка суффикса |

**Урок для методики**: краш-тест регэкса по исходникам, которые *показывают
код как данные* (code-block, blocks с примерами), даёт ложные срабатывания.
Реальных нарушений переносимости (импорт приложения, сеть, XSS) в каталоге
**не найдено**. Это хороший знак — самодостаточность соблюдается.

### Тёмная тема: нет `light-dark()` — 33 items

Вся категория **layout (все 19)** без `light-dark()` — каркасы, вероятно,
осознанно нейтральные, но проверить: в тёмной теме превью может остаться
белым. Остальные: accordion-011, alert-018, aspect-002, button-022,
carousel-006, collapsible-004, toggle-011, auth-033, footer-016..018,
navbar-008, background-002, stack-012.

### Доступность

- `img` без `alt`: card-012, faq-015, hero-007, hero-010.
- Нет фокус-стилей при интерактивных элементах: portfolio-004, waitlist-003,
  code-block-anim-001.

### Размер файла (вес страницы пользователя)

- Огромные (>28KB): background-001 (42KB), background-003 (33KB),
  cursor-001 (29KB), background-004 (28KB).
- Большие (19–24KB): command-014, date-012, date-013, datagrid-017,
  datagrid-019, hero-002, navbar-004/007/010/011, background-002/005,
  button-anim-001.

### Прочее

- Inline-стили >3: hero-002, checklist-001 (допустимо, если значения
  динамические — глазами проверить).

*Хорошая новость: `prefers-reduced-motion` есть во всех анимированных items
без исключения; `any` не используется нигде; кнопки в формах типизированы.*

## Слой 2. Визуальный проход по категориям

Просмотр в тёмной теме (в ней дефекты контраста и «белых дыр» заметнее),
светлая — точечно для items с флагом `no-light-dark`.

### Компоненты

#### Аккордеон (14) — ✓

Ассортимент сильный: нативный, карточный, с подсветкой, плотный, чеклист,
двухуровневый, лента событий, тёмный, с постоянными ссылками. Различимость
items хорошая. Недостатки:

- **Мета-контент как демо**: AC001, AC010, AC012, AC014 используют FAQ про
  сам VibeUI («Что я получаю после установки?», «Почему своя палитра?»).
  Самоописание вместо нейтрального примера: агент пользователя рискует
  утащить этот текст в чужой сайт, и один и тот же контент повторяется в
  четырёх items — выглядит как копипаста.
- **Воздух в превью**: почти каждое превью на ~40–50% пустое сверху и снизу
  — это витрина, не компонент, но глазу кажется, что показывать нечего.
- AC011 (тёмный) — осознанно без `light-dark()`, в тёмной теме отличен;
  проверить светлую подложку превью.

#### Уведомление / alert (20) — ✦

Лучшая широта из просмотренных: inline, заливное, у поля, с выбором,
закрываемое, новинка, комментарий, прогресс, отсчёт, ошибки формы,
обновление, cookie, статус, лимит, сгруппированные, работы, офлайн,
инструкция, подтверждение словом. Недостатки:

- **AL002 (заливное)**: тёмно-красный текст на красно-оранжевой заливке —
  контраст на грани читаемости в тёмной теме. Проверить по WCAG.
- **AL006, AL012**: демо-контент — самореклама VibeUI («Панель кода прямо
  в каталоге»). Тот же грех, что у аккордеона.
- **AL013 (Consent Alert)** дублирует смысл категории «Согласия» — граница
  категорий смазана, человек не поймёт, где искать cookie-баннер.
- **AL020 (Confirm Word)** — по сути alert-dialog, а не alert: категория
  выбрана спорно.
- Вся категория живёт в одной легенде «конструктор сайтов» — консистентно,
  но однообразно (см. общий вывод про SaaS-монокультуру демо-контента).

#### Диалог подтверждения / alert-dialog (14) — ~

Сам диалог (проверен кликом) качественный: затемнение, фокус на главной
кнопке, вменяемые тексты. Главный недостаток — **витрина слепая**:

- **Все 14 превью показывают только кнопку-триггер** («Опубликовать»,
  «Удалить проект», «Стереть все данные»…). Сам диалог — то, ради чего
  человек пришёл, — не виден без клика по каждому превью. Выбор глазами
  невозможен: 14 одинаковых карточек с одной кнопкой посередине. Нужен
  режим превью «диалог открыт» (как минимум статичный отпечаток).
- Различимость items по названиям хорошая (ввод для подтверждения,
  массовое, с задержкой, с итогом, с галочкой…), но визуально в каталоге
  они неотличимы.

#### Пропорции кадра / aspect-ratio (8) — ✓

Единственная категория с настоящими фотографиями — сразу дороже выглядит.
Видео-кадр, товар, портрет, коллаж, карта, скелетон галереи. Недостатки:

- **AS003 (кадр товара)**: фото городской улицы подписано «Настольная
  лампа „Полёт", тёплый свет» — картинка не соответствует товару, в
  витрине выглядит ошибкой.
- **AS005 (кинематографичный баннер)**: белый текст «Соберите страницу за
  вечер» лежит на светлой части фото — читается плохо; бирюзовая кнопка
  выбивается из палитры; контент — опять самореклама VibeUI.
- AS001: кадр приглушён сине-серым тоном и выглядит «мёртвым» рядом с
  живыми соседями.

#### Автодополнение / autocomplete (15) — ✦

Один из сильнейших разделов: живые открытые дропдауны в превью, командный
поиск, упоминания @, домен почты с Tab, «подсказки не загрузились —
повторить» (редкое честное состояние ошибки), поиск с превью документа.
Недостатки:

- **Открытые дропдауны вылезают за границы карточки превью** и при
  прокрутке перекрывают шапку каталога и соседние карточки (список
  «Казань/Калуга» наезжает на меню). Дефект витрины: overflow превью не
  изолирован.
- A0014 показан в категории первым, до A0001 — порядок сортировки items
  выглядит случайным.
- A0004 (командный поиск) функционально дублирует категорию «Командное
  меню» — граница категорий размыта.

#### Аватар / avatar (31) — ✓

Настоящие фото людей, широкий состав: стек, кольца статусов и ролей,
печатает/говорит, загрузка и обрезка фото, шапка профиля, меню профиля.
Недостатки:

- **AV037 (генеративный аватар): превью пустое** — компонент ничего не
  отрисовал в карточке каталога. Для покупателя выглядит сломанным.
- **Фотопул из ~6 лиц**: одна и та же блондинка в AV001, AV002, AV004,
  AV006, AV013, AV015… — витрина выглядит однообразной, стопки «команды»
  собраны из одних и тех же людей.
- AV025: подпись «Руководитель… направления клиентского» — многоточие
  посреди двух строк, обрезка текста выглядит багом переноса.
- Коды items с дырками (AV028, AV030, AV031, AV033…AV039 при «31
  компонент») — следы удалений, нумерация непоследовательная.
- AV018: цветные подписи ролей мелкие, контраст на тёмном слабый.

#### Плашка / badge (25) — ✦

Ровная сильная категория: статусы, счётчики, тренды, версии, чипы фильтров,
обрезка длинных названий веток, key-value. Замечания мелкие:

- BA005: оба демо-чипа — «Москва», выглядит копипастой; варианты цветов в
  BA001/BA002/BA013/BA014/BA017 показаны одним и тем же словом
  («Опубликовано» ×3) — легально, но однообразно.

#### Баннер / banner (15) — ✓

Объявление, обновление, cookie, лимит, офлайн, работы, промо с отсчётом,
подтверждение почты, режим чужого имени, стопка, установка приложения.
Недостатки:

- Сильное **пересечение с категорией «Уведомление»**: BN003/BN013 (cookie)
  = alert consent; BN006/BN011 (офлайн) = AL018; BN009 (почта) — та же
  сцена. Человек не поймёт, чем баннер отличается от уведомления.
- Демо-контент почти весь — самореклама VibeUI (BN001 «Каталог пополнился»,
  BN015 «VibeUI работает офлайн»).
- BN012/BN008: промо-акция и отсчёт — уводят в маркетинг, категория теряет
  фокус (баннер как системная плашка vs рекламный блок).

#### Хлебные крошки / breadcrumb (15) — ✓

Сворачивание, слеш, от главной, раскрытие, прокрутка, путь к файлу, мастер
(шаги), со счётчиком, типы узлов. Замечания:

- BD007 демо = «Компонент breadcrumb-007», BD008 = «breadcrumb-008.tsx» —
  самоописательные плейсхолдеры вместо реального пути.
- BD006 показывает мета-заголовок «Хлебные крошки · 12 компонентов» внутри
  превью — витрина каталога просочилась в демо компонента.

#### Кнопка / button (76) — ~

Самая крупная категория и самая «раздутая». Механика кнопок отличная (action,
split, magnetic CTA, loading, icon, tooltip icon, reveal password), но:

- **Сильный scope creep**: под «кнопкой» лежат явно не кнопки — BU058 «поле
  пароля» (это input), BU057/BU060 чипы-счётчики/фильтры (это badge/chip),
  BU029/BU059 целые футеры форм с полями. 76 — это раздувание счётчика за
  счёт чужих категорий. Для находимости вредно: ищешь кнопку — получаешь
  поля и чипы.
- button-022 (статика) — без `light-dark()`.
- Как везде: демо-контент — «Опубликовать / Отправить заявку / VibeUI».

#### Группа кнопок / button-group (57) — ~

Богатейший набор (сегменты, тулбары, пейджеры, пресеты, реакции, выбор
колонок…). Проблемы те же структурные:

- **Раздутость и scope creep**: BT014 «Вкладки только с иконками» = tabs,
  BT017/BT018 переключатели = toggle-group, BT044 «Счётчик количества» =
  number-field, BT022/BT044 степперы. 57 items — во многом за счёт соседних
  категорий.
- (Ложная тревога, снята после проверки: BT034 существует в registry;
  «пропажа кода» была артефактом моего скрипта-сборщика заголовков, у
  превью-карточек бывает собственный h3.)

#### Календарь / calendar (30) — ✦

Одна из лучших категорий по глубине и без scope creep: сетка, диапазон,
слоты, повестка, тепловая карта загрузки, цены по дням, график смен,
ISO-недели, два часовых пояса, правило повтора, почасовое бронирование.
Визуально аккуратно, «сегодня» и диапазон читаются. Замечаний по качеству
почти нет; демо-даты приведены к «март 2026» консистентно.

#### Карточка / card (23) — ~

Хороший набор форм (материал, показатель, человек, товар, выбор, добавление,
скелетоны, файл, цитата, delta-tile, flip). Но **самый яркий носитель
монокультуры демо-контента**: почти каждый item про сам VibeUI/обучение —
«Как собрать лендинг за вечер», «Собрать каталог компонентов», «Что такое
container queries», «Сборка каталога на container queries», «Курс: раскладка
без медиазапросов», «Волна карточек в каталог», «Открытая встреча по
дизайн-системам». Вайбкодер, выбирающий карточку под свой сайт, видит
рекламу платформы, а не нейтральный образец. card-012 — `img` без `alt`
(статика).

#### Карусель / carousel (19) — ✓

Настоящие фото, сильные приёмы: snap, peek, marquee логотипов, слайдер
отзывов, лайтбокс, cross-fade, куб. Замечания:

- carousel-006 — без `light-dark()` (статика), проверить светлую тему.
- Демо-контент снова про VibeUI («Как собрать лендинг за вечер», «Токены
  без болей»).
- Категория «галерея» ищется сюда, но настоящей grid-галереи нет — см.
  отдельный отчёт по доработкам (раздел «Галерея»).

#### Каскадный выбор / cascader (20) — ✦

Без scope creep, разнообразные домены (доставка, счета, врач, оборудование,
оргструктура), ленивая подгрузка уровней, поиск по дереву, полный путь.
Крепко, замечаний по качеству нет.

#### График / chart (29) — ✦

Очень широкий и качественный набор (линия, столбцы, кольцо, спидометр,
воронка, водопад, scatter, радар, тепловая карта, punch card, budget
bridge). Единственное:

- **Палитра диаграмм отходит от бренда**: кольцо «Источники трафика»
  (CH003) — сине-фиолетово-розовые секторы вместо оранжевой гаммы
  брендбука. Категориальная палитра графиков не привязана к теме — проверить
  на соответствие BREND.

#### Флажок / checkbox (23) — ✓

Строки, выбор, родительский, дерево прав, матрица доступа, согласия
(несколько видов). Замечания:

- Пересечение: CE019 «Чипы фильтров» = badge/filters, CE004 «Список
  фильтров» = filters. Мелкий scope creep.
- Много вариантов «согласия» (CE005/CE013/CE020) — дублируют категорию
  «Согласия» в блоках.

#### Блок кода / code-block (31) — ✦

Отличная категория: подсветка синтаксиса, diff, вкладки менеджеров пакетов,
терминал, JSON-дерево, маскировка env, выноски к строкам, трассировка,
журнал с уровнями. Замечания:

- **Аномалия порядка**: CF031 «Блок кода» стоит между CF027 и CF028 —
  сортировка по номеру нарушена (скорее всего добавлен позже, индекс не
  пересчитал порядок в витрине).
- Демо-код почти везде про установку самого VibeUI (`npx shadcn add
  codeblock-004`, `@/components/ui/button`) — уместно для code-block, но
  усиливает общий эффект самоописания каталога.

#### Сворачиваемый блок / collapsible (9) — ~

Механика хорошая (native disclosure, animated height, exclusive steps,
sticky sections). Но **100% демо-контента — про сам VibeUI**: «Как
устанавливается компонент», «Что входит в поставку», «Почему компонент
отдаётся одним файлом», а CP004 — фейковый лог сборки с «warn
collapsible-004: preview шире карточки». Ни одного нейтрального примера.
collapsible-004 — без `light-dark()` (статика, тёмный терминал).

#### Поле с подсказками / combobox (27) — ~

Качество высокое (группы, чипы, виртуализация, ranked, preview pane,
debounce). Главная проблема — **дублирование категории autocomplete**:
People Picker, Async Check, Recent First, Create Option, Hotkey Open,
Thumbnail Options присутствуют и там, и там. 27 + 15 items двух категорий
решают одну задачу «поле с выпадающими подсказками». Граница между ними
не считывается ни человеком, ни поиском.

#### Командное меню / command (15) — ~

Богатая палитра (nested, project search, go-to-file, ask AI, tabs, bloom).
Проблемы:

- **Витрина слепая, как у alert-dialog**: половина превью (CN001/002 и
  далее) показывает только кнопку-триггер «Открыть палитру Ctrl+K», сама
  палитра не видна без клика. Выбор глазами затруднён.
- command-014 — крупный файл 20KB (статика).
- Пересечение с autocomplete (Command Search) и combobox (Hotkey Open).

#### Контекстное меню / context-menu (10) — ✓

## Итоговые выводы и приоритеты

### Что хорошо (сильные стороны)

- **Механика каталога отличная.** «Выбрал → скопировал для ИИ → агент
  поставил» работает; ссылка `/c/<name>` отдаёт агенту команду, fallback,
  пропсы, запрет пересоздавать. Это лучшее в проекте.
- **Инженерное качество высокое и однородное.** Собственная палитра
  `--vibeui-<name>-*`, `light-dark()`, `prefers-reduced-motion` (в 100%
  анимаций), ноль `any`, самодостаточность — соблюдаются почти везде.
- **Ассортимент глубокий и продуманный.** Многие категории (calendar,
  chart, pagination, stepper, filters, tabs, rating, sortable) закрывают
  редкие состояния (ошибки, пустота, загрузка, a11y-клавиатура).
- **Тёмная тема и превью работают корректно** у подавляющего большинства
  просмотренных категорий (исключения — ниже, п. 6).

### Реальные проблемы (по важности)

1. **Монокультура демо-контента (самая массовая проблема).** Почти весь
   контент — про сам VibeUI / SaaS-лендинг («Запускайте продукт вдвое
   быстрее», «Собрать каталог», «Курс: раскладка без медиазапросов»).
   Сильнее всего в card, collapsible, hero, blocks. Вайбкодер выбирает
   глазами и видит рекламу платформы, а не нейтральный образец под свой
   сайт. → разбавить примеры (игра, кино, еда, спорт), см. отдельный отчёт
   по доработкам, п. 3.

2. **Раздувание счётчика «1584» дублирующими категориями.** Подтверждённые
   кластеры пересечений:
   - **Поля ввода**: input (32) + input-group (40) + field (12) +
     native-select (7) + currency-input (7) + phone-input (9) + label (13)
     — валюта/телефон/префикс/кнопка-в-поле повторяются в 3-4 категориях.
   - **Выпадающие**: select (33) + combobox (27) + autocomplete (15) +
     native-select (7) + dropdown-menu (22).
   - **Тумблеры**: toggle (15) + toggle-group (19) + switch (16) + часть
     button-group (57).
   - **Оверлеи**: popover (14) поглощает tooltip/dialog/hover-card/
     dropdown/date-selector «во всплывашке».
   - **Уведомления**: alert (25) + toast (25) + banner (15) + notifications.
   Вредит находимости: по «поле»/«меню» вайбкодер тонет в почти одинаковом.

3. **Слепая витрина у оверлей-компонентов.** alert-dialog, command, drawer,
   popover (и частично hover-card, tooltip) показывают в каталоге только
   кнопку-триггер — само содержимое не видно без клика. Выбор глазами
   невозможен. → режим превью «открыто» (хотя бы статичный отпечаток).

4. **Вес анимированных фонов/курсоров.** background-001 42KB, 003 33KB,
   004 28KB, cursor-001 29KB (+ аним-фоны 21-28KB) — самые тяжёлые файлы.
   На слабой машине и мобильных дорого. → пометка «тяжёлый» + статичный
   fallback.

5. **Точечные a11y/контраст.** `img` без `alt`: card-012, faq-015,
   hero-007, hero-010. Нет фокус-стиля: portfolio-004, waitlist-003,
   code-block-anim-001. Контраст на грани: alert AL002 (тёмно-красный текст
   на красной заливке). aspect AS003 — картинка не соответствует подписи.

6. **«Белый блок в тёмной теме» — подтверждён глазами.** `light-dark()`
   нет у 33 items; визуально проверено: **вся категория layout (LA002
   „Каталог мебели" — идеальный каркас каталога героев) рендерится светлой
   панелью на тёмной странице**; аним-media (ME001/002 аудио/видео)
   тоже светлые карточки. Для тёмного «игрового» сайта — реальный дефект.
   Досмотреть остальные no-`light-dark` (footer-016..018, navbar-008,
   background-002 и др.).

7. **Off-brand синий/радужный — сквозная тема.** В data-viz: chart (кольцо
   CH003 сине-фиолетовое), icon-tile. В анимациях: particle sphere (синий),
   аудиоволна (синяя), щит security (синий), рамка видеоплеера (радужная).
   Бренд — оранжевый (BREND.jfif); семантические зелёный/красный оставить,
   но декоративный синий свести к бренду.

8. **map-блоки встраивают внешние карты.** MA001 реально тянет
   Яндекс.Карты (+ошибка в консоли от embed). Единственная категория, не
   способная быть полностью самодостаточной — неизбежно для карт, но стоит
   пометить в metadata как «внешняя зависимость».
