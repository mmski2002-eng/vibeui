# Личный кабинет: что сделано по аудиту

Дата: 10 сентября 2026 года. Основание: [AUDIT-ACCOUNT-UX.md](AUDIT-ACCOUNT-UX.md).
Статус: реализованы все замечания разделов 5, 7, 8, 9 и порядок работ из
раздела 10. Изменения лежат в рабочем дереве, на production не выложены.

## 1. Целостность сценариев (первая итерация аудита)

| Замечание аудита | Что сделано |
| --- | --- |
| P1. Английский вход ведёт на несуществующий `/en/account` | Кабинет собран как компоненты с параметром языка (`components/pages/account/*`), маршруты продублированы: `app/account/*` и `app/en/account/*`. Тексты — `components/account/texts.ts` (ru/en). Middleware закрывает обе ветки, английский кабинет разворачивает на `/en/signin`. |
| P1. Потеря контекста: callback ведёт на `/`, `returnTo` не сохраняется | Middleware кладёт исходный адрес в `?next=`, `requireUser()` делает то же через заголовок `x-vibeui-path` (`lib/session.shared.ts`). Формы входа и регистрации возвращают человека туда же; письмо подтверждения приходит с `callbackURL` на `/verify?state=done&next=…`. Адрес проверяется `safeNext()` (`lib/safe-path.ts`): только внутренний путь, без `//`, схем и управляющих символов. |
| P1. Нет повторной отправки подтверждения | Отдельный экран `/verify` (`components/auth/verify-panel.tsx`): адрес, срок жизни ссылки, кнопка повторной отправки, отдельные состояния «подтверждено», «ссылка устарела», «ссылка уже использована». Кнопка повтора есть и в профиле. Лимит на сервере: `/send-verification-email` — 3 запроса за 5 минут. |
| P1. `spendItem()` не пишет `usage` для Pro | Запись в `usage` делается и для подписчика (`lib/entitlements.ts`): подписка снимает лимит, а не историю. |
| P1. Согласие проверяет только браузер | Форма присылает `consentVersion` (`lib/consent.ts`), серверный хук сверяет её и отклоняет регистрацию с `BAD_REQUEST`, если версии нет или она чужая. Дату по-прежнему ставит сервер. |
| P1. Разные представления подписки | Одно состояние на весь сайт: `lib/subscription-state.ts` — `free`, `pro`, `bonus`, `cancelled`, `past_due`, `expired`. Им пользуются оболочка кабинета, обзор и страница оплаты. Про следующее списание сказано только там, где оно действительно будет. |
| P1. Ошибки форм слиты в одну строку | `try/catch/finally` во всех формах: вход, регистрация, восстановление, новый пароль, смена пароля, продление подписки, выпуск ключа. Разведены неверные данные, неподтверждённая почта, лимит попыток, истёкшая ссылка и обрыв сети. Нейтральный ответ для неизвестной почты сохранён. |

## 2. Оболочка и рабочие панели (вторая итерация)

- **Навигация** (`components/account/account-nav.tsx`): две группы — «Библиотека»
  (Обзор, Избранное, История) и «Аккаунт» (Тариф и оплата, Подключение к
  проекту, Приглашения, Профиль и безопасность), иконки `lucide-react`,
  закреплённая колонка на desktop. На телефоне — строка с названием текущего
  раздела и раскрывающееся меню: активный раздел больше не уезжает за край.
- **Профиль** ужат до карточки в колонке (`components/account/account-shell.tsx`),
  выход — иконкой рядом с именем. Широкая полоса над содержимым убрана.
- **Обзор** (`components/pages/account/overview.tsx`): сверху «Продолжить
  работу» с живым превью последнего взятого компонента и действиями «Открыть»
  и «Копировать для ИИ», затем сохранённое, затем компактная история. Лимит —
  строка со шкалой в правой колонке вместо ста делений. Для нового аккаунта —
  три шага и кнопка «Выбрать первый компонент».
- **Избранное** (`favorites-grid.tsx`): поиск, фильтр по типу, живые превью,
  «Копировать для ИИ», удаление с возвратом («Убрано — Вернуть»), подгрузка
  по 12 карточек.
- **История** (`history-list.tsx`): компактные строки, поиск, выбор месяца,
  подгрузка, счётчик показанного. Подпись честная: строка появляется при
  первом обращении к компоненту в месяце, это не счётчик копирований.

## 3. Настройки и завершённые состояния (третья итерация)

- **Тариф и оплата** (`billing.tsx`, `billing-parts.tsx`): полноценная карточка
  бесплатного тарифа вместо пунктирного «Подписки нет»; статусы платежей
  (оплачен, ожидает, отменён, возвращён), продолжение списка, панель ожидания
  подтверждения оплаты с кнопкой обновления, ошибка операции продления видна.
- **Подключение к проекту** (`connect.tsx`, `token-panel.tsx`): три шага
  установки, команда с копированием, ключ — ниже. Замена ключа подтверждается
  отдельно, новый показывается один раз с кнопкой копирования, отзыв
  подтверждается, ошибка операции не молчит. На сервере: право проверяется в
  `createRegistryToken()`, отзыв и выпуск идут одной транзакцией.
- **Приглашения** (`referrals.tsx`): ссылка и копирование одной панелью,
  счётчики строкой, история начислений. «Дней Pro» переименовано в
  «Начислено за приглашения» и считается суммой `daysGranted`.
- **Профиль и безопасность** (`profile.tsx`, `profile-panels.tsx`): имя, язык
  писем, статус подтверждения почты с повторной отправкой, смена пароля с
  разбором причин отказа, список устройств (браузер, система, время) и
  завершение остальных сессий. Место по IP не показываем.
- **Загрузка и ошибка**: `loading.tsx` со скелетоном по форме панелей и
  `error.tsx` с повтором без потери контекста — в обеих языковых ветках.

## 4. Вход и регистрация

- Двухчастная композиция (`components/auth/auth-card.tsx`): слева обещание и
  три настоящих превью из каталога, справа форма шириной 26rem. На телефоне
  витрина скрыта.
- Показ пароля (`components/auth/password-input.tsx`), вставка не запрещена,
  поля 44px, менеджеры паролей работают через `autoComplete`.
- Тексты переписаны: «Соберите свою библиотеку дизайна», «Вернитесь к своей
  библиотеке», подзаголовок про 100 компонентов в месяц.
- После сброса пароля вход показывает «Пароль обновлён. Войдите с новым
  паролем»; истёкшая ссылка предлагает запросить новое письмо.

## 5. Палитра и контраст

Заливка кнопки и цвет текстовой ссылки разведены: добавлен токен
`--shell-accent-text` (`app/globals.css`). В светлой теме он темнее брендового
`#FF5900`, чтобы обычный текст проходил 4.5:1
([W3C, Contrast Minimum](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum/));
в тёмной совпадает с акцентом. Кабинет и формы используют его для надписей,
`--shell-accent` остался для заливок и рамок.

## 6. Как проверено

- Панели кабинета собраны на вымышленных данных на странице `/lab/account`:
  кабинет закрыт сессией и живой базой, локально её нет — иначе вёрстку не
  посмотреть. Проверены обе темы, 1440 и 390 px, раскрытие мобильного меню.
- Формы `/signin`, `/signup`, `/verify`, `/reset` проверены в браузере на 1440
  и 390 px.
- Редиректы проверены запросами: `/account/history` → `/signin?next=%2Faccount%2Fhistory`,
  `/en/account/favorites` → `/en/signin?next=%2Fen%2Faccount%2Ffavorites`.
- `npm run indexes:check` — индексы актуальны.

**Чего проверка не покрывает.** Живой кабинет с данными, письма, оплата и
отзыв ключей локально не запускались: базы и SMTP на машине нет. Эти сценарии
проверяются на сервере после выкладки. `npm run meta:validate` сейчас падает на
чужой незавершённой работе в `registry/blocks/background` (скаффолдные TODO у
`surface-008…012`) — к кабинету это отношения не имеет, файлы не трогались.
Линт, типы и сборка не запускались по правилу проекта.

## 7. Что осталось за рамками

- OAuth и passkeys — аудит сам относит их к следующей итерации.
- Смена почты, удаление аккаунта и выгрузка данных: нужны правила для
  связанных платежей, отдельный сценарий.
- Компактная шапка на страницах входа: сейчас там общая шапка каталога.
- Поле «последнее использование» в истории: требует отдельного события на
  каждое копирование, а не строки на месяц.
