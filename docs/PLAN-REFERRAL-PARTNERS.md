# План: партнёрская реферальная программа (блогеры)

Дата: 12 сентября 2026. Статус: реализовано 12 сентября 2026, ждёт проверки
владельца на живой базе. Решено: бонусных дней
нет и не будет (удаляем из кода), почта реферала маскируется, приглашение
блогера одноразовое, пункт 0 (оранжевый акцент на витрине главной) сделан.

## Что есть сейчас

Реферальная программа уже работает, но открыта всем:

- у любого зарегистрированного при заходе в «Приглашения» создаётся код
  (`referral`, один на аккаунт) и ссылка `vibeui.ru/i/<код>`;
- переход по ссылке кладёт код в куку на 60 дней и пишет `referral_visit`;
- при регистрации хук Better Auth (`lib/auth.ts`) читает куку и ставит
  `user.invited_by` навсегда;
- первый платёж приглашённого начисляет дни Pro обоим
  (`lib/payment-apply.ts` → `referral_reward`): 14 пригласившему, 7 приглашённому;
- кабинет `/account/referrals`: ссылка, переходы, оплатившие, начислено дней.
  Списка людей нет;
- в админке рефералов нет, только три числа на сводке.

## Что нужно

Два уровня. Первый — **партнёры (блогеры)**: их приглашает только
администратор, персональной ссылкой, созданной под имя. Второй — **рефералы
партнёра**: обычные люди, регистрируются по ссылке блогера и привязываются к
нему. Обычный пользователь ссылки не получает.

```
админ ──создаёт──▶ ссылка-приглашение «Имя блогера» /i/<код>
                          │ блогер регистрируется по ней
                          ▼
                     партнёр (аккаунт с правом приглашать)
                          │ своя ссылка /i/<код партнёра>
                          ▼
                     рефералы партнёра (user.invited_by = партнёр)
                          │ оплата подписки
                          ▼
                     видно админу и партнёру: оплатил / не оплатил
```

## Схема данных

Одна новая таблица, остальное уже есть.

```
partner_invite                       ссылка для блогера, создаёт админ
  id            text pk
  code          text unique          часть ссылки /i/<code>
  name          text                 имя блогера, как ввёл админ
  created_by    text                 почта админа
  created_at    timestamp
  claimed_by    text unique null     user.id блогера после регистрации
  claimed_at    timestamp null
```

- «Партнёр» = пользователь, на которого ссылается `partner_invite.claimed_by`.
  Отдельной роли в `user` не нужно: признак выводится соединением.
- `referral` (код партнёра) остаётся как есть, но строка создаётся только
  партнёру. Старые коды обычных пользователей не удаляются (продовые данные),
  просто перестают резолвиться.
- `user.invited_by` остаётся привязкой реферала к партнёру.
- `referral_visit` пишется и для приглашений блогеров, и для их ссылок:
  колонка `code` общая.
- В `admin_action.target_type` добавляется `partner` — создание и удаление
  ссылки попадают в журнал.

Миграция: `drizzle/0003_partners.sql` через `npm run db:generate`,
применяется деплоем (`npm run db:migrate`, как 0001 и 0002).

## Поток регистрации (`lib/auth.ts`, хук `user.create`)

Кука `vibeui_ref` несёт код. Порядок разбора:

1. код совпал с **незанятым** `partner_invite.code` → это блогер:
   `invited_by = null`; в хуке `after` записать `claimed_by/claimed_at` и
   сразу создать ему `referral` (свой код);
2. код совпал с `referral.code`, чей владелец — партнёр → обычный реферал:
   `invited_by = владелец`;
3. иначе (занятое приглашение, код бывшего «общего» реферала, мусор) →
   ничего, регистрация обычная.

Ссылка блогера одноразовая: второй человек по ней партнёром не станет и
рефералом не станет. Админ видит на странице ссылки, что она уже занята.

Никаких начислений при регистрации и оплате нет. Реферал получает ровно
то, что купил; блогер — процент от оплаты, который считается вне сайта по
аналитике (процент решим позже, в базе он пока не хранится).

## Удаление бонусных дней

Экономика теперь одна: бесплатно — лимит копирований в месяц, подписка —
безлимит, блогеру — доля от оплаты. Механика «дни Pro за приглашение»
удаляется целиком:

- `lib/payment-apply.ts`: `rewardInviter` и вызов из обработки платежа;
- `lib/plans.ts`: `REFERRAL_DAYS`;
- `lib/db/schema.ts`: таблица `referral_reward` (в миграции `DROP TABLE`);
- `lib/admin-stats.ts`: счётчик начисленных дней на сводке;
- `components/pages/account/referrals.tsx`: «начислено», список начислений;
- тексты ru/en: `referrals.lead/earned/days/rewards*`, «как это считается».

План тарифа `bonus` (`subscription.plan = "bonus"`, подпись «Бонусный Pro»,
`grantDays`) используется ещё и ручной выдачей из админки
(`grantProDays` на карточке пользователя: компенсация за сбой, тест
подписки без оплаты). Его трогать не предлагаю: это инструмент поддержки, не
награда. Если нужно убрать и его — скажи, уйдут `grantDays`,
`grantProDays`, кнопка в админке, ветка `bonus` в `subscription-state.ts`
и в кабинете.

## Маршрут `/i/[code]`

Резолвит два источника: `partner_invite` (только незанятые) и `referral`
(только партнёрские). Кука и `referral_visit` — как сейчас. Чужой или
устаревший код → редирект на главную без куки.

## Админка

### `/account/admin/partners` — список

- форма «Имя блогера» → кнопка «Создать ссылку». Серверное действие
  `createPartnerInvite(name)`: код 8 символов base64url (как у `referral`),
  запись в `partner_invite` и в журнал;
- таблица: имя, ссылка (кнопка «скопировать»), создана, статус
  («не зарегистрировался» / «зарегистрировался 3 сен, почта»), рефералов,
  из них оплатили. Сортировка по дате создания;
- удаление незанятой ссылки (занятую удалять нельзя: за ней аккаунт и
  привязки).

### `/account/admin/partners/[id]` — аналитика блогера

- шапка: имя, ссылка-приглашение, переходов по ней, дата регистрации,
  ссылка на карточку пользователя в `/account/admin/users/[id]`;
- партнёрская ссылка блогера, переходов по ней;
- список рефералов: имя, почта, дата регистрации, подписка
  («оплатил 5 сен, активна до …» / «истекла» / «не оплачивал»), сумма
  платежей. Источник: `user.invited_by = блогер` + `subscription` +
  `payment`. Страница по 50 строк с курсором `before`, как в `users`.

Пункт «Партнёры» в группу админа навигации (`account-nav.tsx`), иконка
`Handshake`.

## Кабинет партнёра — `/account/referrals`

- пункт навигации и страница показываются только партнёру; остальным
  пункт скрыт, прямой заход → 404 (как у админки: раздел не существует);
- сверху: ссылка, переходов, зарегистрировалось, оплатили;
- новый блок «Мои рефералы»: дата регистрации, кто (имя и почта в
  замаскированном виде `iv***@gmail.com`: блогер не должен получать базу
  адресов), статус «оплатил» / «не оплачивал». Без сумм;
- текст «как это считается» переписать под партнёра.

## Промокоды

Продолжение программы: ник блогера как промокод со скидкой на первый платёж,
платёж помнит партнёра — [PLAN-PROMO-CODES.md](PLAN-PROMO-CODES.md).

## Решения

- Старые ссылки открытой программы удалены миграцией (`referral`,
  `referral_visit` очищены), привязки `invited_by` остались как история.
- Ручная выдача дней из админки (`grantProDays`, план «Бонусный Pro»)
  оставлена как инструмент поддержки.

## Как проверить

1. Применить `drizzle/0003_partners.sql` (деплой делает сам через
   `scripts/migrate.sh`; локально — `npm run db:migrate` или psql).
2. Админом открыть `/account/admin/partners`, создать ссылку с именем.
3. В приватном окне перейти по ссылке, зарегистрироваться — в списке у
   админа появится «зарегистрировался», у нового аккаунта в кабинете
   появится пункт «Рефералы».
4. Скопировать ссылку партнёра, в другом приватном окне зарегистрироваться
   по ней — реферал появится и у партнёра, и у админа на странице блогера.
5. Тестовый платёж реферала → статус «оплатил» в обоих списках.
6. Повторная регистрация по ссылке-приглашению блогера никого партнёром не
   делает; аккаунт без приглашения на `/account/referrals` получает 404.
