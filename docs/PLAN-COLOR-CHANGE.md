# План: уйти от фирменного оранжевого

Дата: 12 сентября 2026. Статус: выбран чернильный, шаги 1–5 и 7 выполнены 12 сентября 2026; шаг 6 (сайт и брендбук) по решению владельца не делается.

## Что есть сейчас

Оранжевый `oklch(0.68 0.21 39.8)` — единственный акцент проекта. Он не
«где-то в теме»: каждый item несёт его в своей палитре `--vibeui-<name>-*`.

| Где | Файлов с оранжевым | Всего | Вхождений |
|---|---|---|---|
| `registry/components` | 937 | 1182 | 2462 |
| `registry/blocks` | 288 | 358 | — |
| `registry/animations` | 13 | 53 | — |
| Сайт: `app/globals.css` | `--primary`, `--ring`, `--shell-accent*` | | 9 |
| Лендинг, шапка | классы `shell-accent` | | |
| Metadata `registry.json` | слово «оранжевый» в описаниях | 153 | |
| `BREND.jfif` | брендбук | | |

Оранжевый везде записан одинаково: `oklch(L C 39.8)`, где L и C свои у
каждого компонента (кнопка ярче, кольцо фокуса прозрачнее, подложка чипа —
12 %). Поэтому замена делится на два разных по природе шага.

## Шаг 0. Выбрать новый первичный цвет

Это решение бренда, оно твоё. Кандидаты на превью в
`docs/color-candidates/` (кнопки, поля, карточки, тёмная тема):

| Вариант | Оттенок | Файлы | За | Против |
|---|---|---|---|---|
| Синий | `hue 250` | `*-blue.png` | привычный для UI, спокойный, хорошо с серым | «как у всех»; сливается с info-состояниями |
| Индиго | `hue 280` | `*-indigo.png` | современный, узнаваемый, не конфликтует с семантикой | холоднее, на тёмной теме требует чуть больше светлоты |
| Бирюзовый | `hue 185` | `*-teal.png` | свежий, отличается от конкурентов | близок к «успеху», зелёные состояния придётся разводить |
| Чернильный | `chroma 0` | `*-ink.png` | вне времени, семантические цвета читаются ярче, ничего не спорит с контентом пользователя | нет «фирменности», акцент несут только форма и типографика |

Рекомендация: **чернильный** для компонентов и **один цветной** акцент
только для сайта-витрины. Библиотека компонентов не должна навязывать
бренд чужому проекту: пользователь ставит item в свой сайт, и нейтральный
акцент ложится в любую палитру. Если хочется цветного — индиго.

Нужно от тебя: вариант из таблицы или свой oklch.

## Шаг 1. Механическая замена оттенка

Один скрипт по всем трём деревьям registry: `oklch(L C 39.8)` →
`oklch(L C <новый hue>)`. Светлота и насыщенность каждого компонента
остаются, поэтому контраст кнопок, колец и подложек не ломается, а
`on-accent` во многих items считается формулой от светлоты и подстроится сам.

Для чернильного варианта замена сложнее: chroma → 0, а светлота
переворачивается (тёмный акцент на светлой теме, светлый на тёмной).
Скрипт есть, но ~40 items с градиентами и «мягкими» подложками потребуют
ручной проверки.

Объём: ~1240 файлов, один прогон, ~10 минут. Плюс `app/globals.css` и
классы `shell-accent` на сайте.

## Шаг 2. Семантическая правка

Там, где оранжевый работал не как акцент, а как «внимание» — только потому,
что оранжевый похож на янтарный. После смены оттенка эти места станут
неправильными и получат явный янтарный:

BN005 квота, BN010 «работаете от имени», BN011 офлайн, DI014 сессия
заканчивается, CA020 отсчёт до срока, CA023 «вне часов», AL009 пробный
период, AL015 лимит, PG006 порог, SL011 и CS018 статусные точки
«в работе», TR014 приоритет, SL028 «средний», BT051 уровни приоритета,
PO003/DO007 опасные зоны (проверить, что там красный).

Оценка: ~20 items, вручную, по одной переменной.

## Шаг 3. Данные и графики

Одиночная серия (CH001, CH002, CH004, CH006, CH007, CH011, CH012, CH016,
CH017, CH026, SA003, SA005, RN002, PG001–PG005) → новый первичный,
подстроится шагом 1. Тепловые карты и шкалы (CH021, CH025, CH029, CA007,
CA016) — градиент от нового оттенка, подстроятся шагом 1, но глазами
проверить читаемость 5 ступеней. Двухсерийные (CH009, CH028) — второй
цвет остаётся серым.

## Шаг 4. Декоративное

Градиенты и заливки с оранжевым в составе: AV021 кольцо истории, PG007
полосатый индикатор, BN008/BN012 промо, AV009 аватар ассистента, CR022
дата события, CS018. Хью меняется шагом 1, но сочетания (оранжевый +
фиолетовый) после замены могут стать грязными — ~10 items посмотреть
глазами и поправить второй цвет.

## Шаг 5. Тексты

153 metadata упоминают «оранжевый» в описаниях, docs и `ai.preserve`
(«оранжевые маркеры на опорных словах»). Заменить на нейтральную
формулировку «акцентный». Один скрипт по `registry.json`, затем прочитать
diff глазами: где слово было частью смысла (например, «оранжевая полоса
как у стройки» в staging-баннере), переписать вручную.

## Шаг 6. Сайт и бренд

`app/globals.css`: `--primary`, `--ring`, `--shell-accent`,
`--shell-accent-text`, `--shell-ring`, `--shell-accent-deep`,
`--shell-accent-soft`, `--shell-accent-line`. Лендинг использует их через
классы, отдельной правки не нужно. Шапка каталога — точка у «Сценарии»,
активные состояния — тоже через переменные.

`BREND.jfif` — брендбук с оранжевым. Его нужно обновить отдельно, иначе
`CLAUDE.md` продолжит требовать цвет, которого больше нет.

## Шаг 7. Проверка

- `npm run meta:validate`;
- обзорные скриншоты всех 71 категорий компонентов (скрипт аудита уже
  есть) и 34 категорий блоков, просмотр глазами;
- выборочно светлая тема и страница item'а;
- контраст: у items, где `on-accent` задан числом, а не формулой, проверить
  текст на кнопках (скрипт: найти `on-accent:` с литералом).

## Что не делаем

Не пересобираем компоненты и не трогаем их разметку. Не вводим общий
файл токенов: каждый item остаётся одним файлом со своей палитрой, это
правило проекта.

## Что сделано

- Скрипт чернильной замены прошёл 1277 файлов registry: пары `light-dark()`
  получили тёмную краску в светлой ветке и светлую в тёмной, одиночные
  оттенки 35–48 — то же через `light-dark()`, подложки и тени остались
  серыми с прежней светлотой.
- Hex-оранжевый `#ff5900` в 74 файлах (фоны, раскладки, шапки, подвалы,
  анимации текста) заменён по типу подложки: theme-aware блоки — `light-dark(#1a1a1a,#f2f2f2)`,
  фиксированно светлые раскладки — `#1a1a1a`, фиксированно тёмные — `#f2f2f2`,
  NV008 берёт цвет из собственной переменной `ink`. Data-URI волн SU025 — серый.
- Вложенные `light-dark(light-dark())`, появившиеся у пар с разными
  оттенками, развёрнуты; смешанные пары «краска/тёплый» (BN005, CF021,
  OT010, SL026, SL032) переведены в янтарный.
- Семантика вернулась туда, где оранжевый был статусом: SL011 open/progress/review
  — синий/янтарный/фиолетовый, SL028 medium/high — янтарный/красный,
  AC011 и ST012 (тёмные по замыслу) — светлая краска без `light-dark()`,
  SU005 — плоскость краской с инверсной типографикой.
- Metadata: 180 упоминаний «оранжевый» → «акцентный», 191 «orange» → «accent».
- Радужные градиенты анимаций (`#f97316` в ряду красный→фиолетовый) оставлены:
  это спектр, не бренд.
- Проверено: `meta:validate` зелёный; обзорные скриншоты 71 категории
  компонентов, 33 блоков и 19 анимаций; рискованные блоки в обеих темах.
  Скриншоты в `.playwright-mcp/audit/` (в git не идут).
