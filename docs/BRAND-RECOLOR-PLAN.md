# План перекраски компонентов под бренд (оранжевый #FF5900)

Дата анализа: 2026-09-06. Скоуп: **только `registry/components/*`** —
75 категорий, 1239 items. Блоки и анимации не трогаем.

Эталон выработан на категории `button` (70 items, перекрашена полностью,
build зелёный) — все правила ниже проверены на ней в браузере в обеих темах.

## Палитра

| Роль | Светлая тема | Тёмная тема |
| --- | --- | --- |
| Акцент-заливка (кнопка, бегунок, чип) | `oklch(0.64 0.2144 39.8)` | `oklch(0.6803 0.2144 39.8)` = #FF5900 |
| Акцент, который бывает текстом | `oklch(0.55 0.2144 39.8)` (≥4.5:1 на белом) | `oklch(0.6803 0.2144 39.8)` (5.5:1 на #1A1A1A) |
| Текст на акценте | почти чёрный `oklch(0.15 0.02 39.8)` | тот же |
| Градиентный край | hue `25` (глубокий красно-оранжевый), L/C исходные | так же |
| Рядовой accent-своп | hue → `39.8`, **L и C сохраняются** | так же |

Правило hue-свопа с сохранением L/C — базовое: не ломает контраст
(текстовые акценты остаются тёмными/светлыми как были) и даёт «тинты»
оранжевого как в брендбуке вместо монотонной заливки.

## Инвентарь (из скрипта анализа)

- 1239 items; **144 полностью нейтральных** — уже в бренде, не трогаем
  (kbd 6/6, skeleton 10/10, empty 17/20, icon-stack 5/6, radio-group 15/19,
  icon-tile 12/17, avatar 11/32 и россыпь по одному).
- 1092 items с цветом; **1005 имеют проп `accent`** — конвенция едина.

  объявлений. Плюс произв. `accentsoft/tint/ring/on-accent/soft` (сохраняют
  L/C, наследуют hue-своп автоматически или тем же правилом).
- **188 файлов с градиентами** — тёплая пара 39.8→25 (эталон: button-003).
- **387 inline-значений вне переменных** — кластеризованы по ролям
  (см. dialog: hue 260 = акцент → красим; 30/150/70 = danger/done/warn →
  не трогаем). Горячие точки: dialog 113, frame 49, alert 40, badge 34,
  card 27, avatar 22, dropdown-menu 16, command 12, toast 10, tree 10.
- **41 hex-литерал** — конвертировать вручную по месту.

## Что НЕ красим (семантика)

Суффиксы переменных (195 распознано + дополнение по хвостам):

- статусы: `danger, error, warn, warning, success, done, ok, good, bad,
  critical, alarm, fail, denied, invalid, live, armed, busy, away, online,
  offline, up, down, positive, negative, delta, loss, added, add, del`
- домен: `badge` (форматы файлов), `star` (золото рейтинга — решить глазами),
  `low/mid/high/fair/strong/weak` (шкалы силы пароля), `day/night`,
  `weekend/late`, `string/number/keyword/prompt/entity/type/key`
  (подсветка синтаксиса), `info, new, required, lock`
- логотипы третьих сторон (Google-конус в button-048 и аналоги в соцкнопках)
- identity-цвета аватаров — красим базу в оранжевую семью (эталон
  button-007), различительность через L/C-вариации того же hue

### B. Полуручные — скрипт + разбор inline-значений и градиентов

### C. Особые — ручные решения, красим только нейтральную основу

- **code-block (31)**: подсветка синтаксиса — палитры не трогаем; в бренд
  уводим только accent хрома (кнопки копирования, рамки, активные строки).
- **chart (30), sparkline (5)**: серии данных должны различаться — главная

- **alert (20), badge (25), toast (25), banner (15)**: суть категории —
  статусные тона; красим только accent/info-роль, статусы остаются.
- **rating (9)**: звёзды золотые (hue ~85) или оранжевые — решить глазами
  на превью.

## Фазы

1. **Скрипт-обобщение** `recolor-buttons.mjs` → `recolor-category.mjs`:
   вход — категория; действия: hue→39.8 для не-семантических цветных
   переменных, отчёт по пропущенному (inline, hex, градиенты, семантика) —
   dry-run перед записью. Фильтр семантики — списком суффиксов выше.
2. **Волна A** (механика): пакетами по 5–10 категорий; после каждого пакета
   `lint` + `build`, выборочные превью (3–5 items на категорию, обе темы).
   Коммит на пакет.
3. **Волна B**: по категории за раз; inline-кластеры конвертирует скрипт по
   правилу «hue 240–280 → 39.8, тёплые/зелёные кластеры — глазами», градиенты
   руками по эталону 39.8→25.
4. **Волна C**: ручные решения, каждый пункт отдельным коммитом.
5. **Финал**: полный проход `meta:validate`, `npm run build`, витрина по
   всем категориям в обеих темах, деплой.

Перед каждой волной — коммит-чекпоинт (возможность отката волны целиком).

## Риски

- Жёлтая/янтарная графика на оранжевом фоне сливается (эталон фикса:
  чёрная засечка button-042).
- Тёмные исходные акценты (L<0.5) при hue-свопе дают коричневый —
  поднимать до брендовой пары руками (эталон: button-042 accent).
- Категории-статусы (badge/alert/toast) легко «пересушить»: если после
  перекраски статусные и акцентные элементы неразличимы — откат пункта.
- Метаданные: описания цветов в registry.json встречаются редко, но при
  ручных волнах проверять `description/ai.*` на упоминания цвета.
- `meta.i18n.en`: при любой правке списков ru — счёт пунктов en обязан
  совпасть (валидатор упадёт).

## Оценка

- Волна A: скрипт + проверка — сопоставимо с кнопками ×10, но без ручных
  решений; основной расход — build-циклы и выборочный просмотр.
- Волна B: ~15 категорий × разбор inline.
- Волна C: 4 категории, штучные решения.
