## Задача (как понял)

Проверить главную цепочку MVP end-to-end:

```
каталог → превью → «Копировать для ИИ» → ИИ ставит компонент → результат = превью
```

Метод из ТЗ — «слепой агент»: свежий агент без контекста получает только то,
что получил бы реальный юзер (бриф из кнопки), ставит компонент в чистый
проект, глазами сверяем с превью. Провал = визуальное расхождение. Охват —
весь каталог: компоненты, блоки, анимации, сценарии.

Реализовано в два слоя: **A** — детерминированный аудит доставки/содержимого
по всему каталогу (дёшево, полно); **B** — визуальная ревизия рендера.
Истинный слепой install (реальный `npx shadcn add` в чистый проект) —
частично, см. «Что не покрыто».

## Доставка на уровне кода (проверено чтением)

Цепочка «Копировать для ИИ» цела:

1. **Кнопка требует аккаунт.** `resolveAccess`: аноним → `signin`, кнопка
   показывает замок и НЕ копирует. Даже бесплатные items (лимит на человека,
   не на браузер). Это by design — важно для теста: слепой юзер-аноним кнопкой
   не воспользуется.
2. Кнопка → `/api/registry-source` (проверка вход/Pro/лимит) → подписанная
   `docUrl = /c/<name>?exp&sig` на сутки. В буфер уходит ссылка, не текст.
3. Агент открывает `/c/<name>` → `buildAgentBrief`: правила (top-3 preserve),
   команда `npx shadcn add /r/pro/<name>.json?exp&sig`, deps, usage.
4. `shadcn add /r/pro/<name>.json?sig` → `buildRegistryItem` встраивает
   `content = withPreserveHeader(исходник_с_диска)` — **тот же файл, что
   рендерит превью** (single source of truth) + preserve-заголовок.

Итог: при верной установке файл у юзера байт-в-байт равен превью-исходнику.
Статик `public/r/<name>.json` намеренно **без** `content` (исходник не
раздаётся бесплатно, DELIVERY.md) — install через него не идёт, только через
подписанный `/r/pro`.

## Единственный дефект: `auth-anim-001` (HIGH)

Файл `registry/animations/auth/auth-anim-001/auth-anim-001.tsx`:

- нет директивы `"use client"` (первая строка — `import type …`);
- строка 217: `<form onSubmit={(event) => event.preventDefault()}>` —
  **хардкодный inline-обработчик**.

Server Component с обработчиком события на DOM-элементе → React бросает
`Event handlers cannot be passed to Client Component props` → 500.

Двойной удар:
1. Превью битое у всех (item — pro, но превью видно всем) → 500.
2. Установленный компонент упадёт так же в дефолтной RSC-странице: обработчик
   зашит внутрь, исполняется при собственном рендере в любом контексте, пока
   юзер сам не добавит `"use client"`.

Правка (не применял, только диагноз): добавить `"use client"` первой строкой
файла. Одна строка. Хуков компонент не использует.

### Почему только один, а не 38

Статикой всплыло 38 компонентов с JSX-обработчиком без `"use client"`
(alerts, empties, toasts, banners, часть кнопок, popover-003, avatar-003).
**37 из них — не баг:**

- они берут обработчик **пропом** (`onClick={onConfirm}`), а не зашивают inline;
- в превью проп не передаётся → `onClick={undefined}` → рендер без краха;
- в реальном использовании обработчик всегда приходит от родителя, а родитель
  с функцией обязан быть client-компонентом — туда затягивается и сам компонент
  (React: файл без `"use client"` рендерится в контексте импортёра). Краха нет.

auth-anim-001 отличается тем, что обработчик **не проп, а константа внутри** —
поэтому исполняется всегда. Кросс-проверка двумя методами сошлась: реальный
рендер (обход) и статика дают ровно один always-crash item; хуков без
`"use client"` — ноль.
