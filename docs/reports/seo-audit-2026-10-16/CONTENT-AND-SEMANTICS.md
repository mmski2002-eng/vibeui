| Item (2018 × 2) | индекс, но с порогом качества | у большинства уникальное описание и техзаметки; минимальные primitives (кнопки ×100+) — кандидаты в слабые страницы. Не noindex массово до данных GSC: сначала посмотреть «Просканирована, не проиндексирована» |
| Демо (28 × до 2) | **noindex,follow** или canonical на сценарий | вымышленные компании с адресами/ценами — риск «вводящего в заблуждение» контента и каннибализации со сценарием |

| /legal/offer, /legal/privacy | **вернуть** и индексировать | 404 сейчас; доверие, требование платёжных систем |

## 4. Архитектура и перелинковка (Факт)

- Глубина: главная → корень → категория → item = 3 клика; полный ассортимент доступен краулеру (категории рендерят все items, пагинации нет). Orphan-страниц в sitemap не выявлено на уровне шаблонов (каждый item в списке своей категории и в sidebar соседей).
- Item-страница: ~49 ссылок на соседей по категории в sidebar **до** основного контента в DOM; «Собран из» (части) — хорошо; **нет** ссылок «Используется в сценариях», «Похожие из других категорий», «Блоки, где этот компонент» (обратная связь к «Собран из»).
- Категории: огромные (card 730 КБ, button 617 КБ HTML) — живые рендеры всех вариантов. Риск медленного LCP/INP на мобильных и усечения при обработке очень больших HTML.
- Сценарии → категории (по архитектуре), но обратной ссылки категория → сценарии нет.
- Хлебные крошки визуальные + BreadcrumbList — ок.

Целевая ИА (не ломая catalog → preview → Copy for AI):
`/` → `/blocks|/components|/animations` → категория (интро + фильтр + гайд выбора) → item (превью-скриншот → Copy for AI → install → «Собран из» / «Где используется» / «Похожие») ; параллельно `/scenarios/*` ↔ категории; `/guides/*` → item/категории; `/registry` → install-документация.

## 7. GEO / AI-поиск

- Краулер получает HTML с контентом без JS (SSR) — Факт.
- Сущность VibeUI неоднозначна по имени (см. COMPETITORS). Нужна одна каноническая формулировка «VibeUI — библиотека из ~2000 React/Tailwind компонентов и блоков с shadcn-совместимым registry и ссылкой Copy for AI для агентов» на /about, главной, GitHub, листингах.
- Машиночитаемость: `/r/<item>.json` открыт (200) — сильная сторона для агентов, но `Disallow: /r/` в robots закрывает его и для AI-краулеров. Рекомендация: разрешить `/r/` (это и есть «документация для агентов»), оставив `noindex` через `X-Robots-Tag` для JSON.
- `llms.txt`: сейчас 404 на обоих доменах. Подтверждённого эффекта на ранжирование нет; польза — для агентов, которых пользователь направил на сайт. Рекомендация: сделать дешёвый статический `llms.txt` (что такое VibeUI, как ставить, ссылки на /start, /registry, категории) — как документацию для агентов, не как SEO-меру. P3.
- Ежемесячный тест (вручную): 20 промптов — «best shadcn blocks registry», «UI components for Claude Code», «готовые компоненты для вайбкодинга», «hero section react tailwind with glow»… — фиксировать, упоминается ли VibeUI в ChatGPT search, Perplexity, AI Overviews, Яндекс Нейро.

## 8. CRO органической посадки (item)
- Первый экран item: H1, описание, «Что можно поменять», «Собран из», затем «Копировать для ИИ» — ок. Но в DOM перед ними ~49 ссылок соседей (на мобайле — проверить, не выше ли контента).
- Превью — iframe, инициализируется скриптом (`class="invisible"` в SSR) → до гидрации пользователь видит пустую область; на медленном мобайле — высокий риск плохого LCP и «пустой» первой картинки. Гипотеза до замеров.
- Install-команда скрыта за подписанной ссылкой (30 мин) — для разработчика из органики «где код?» = тупик/регистрация. Для бесплатных items показывать `npx shadcn add https://vibeui.ru/r/<item>.json` прямо в HTML.
- Влияние SEO↔CRO: без видимого кода/скриншота страница слабее и для ранжирования (тонкий видимый контент), и для конверсии (нет доказательства качества).
