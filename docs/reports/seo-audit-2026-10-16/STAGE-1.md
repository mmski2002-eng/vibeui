# Этап 1 — результаты, 2026-10-16

Код изменён только в рабочей копии. Билда, коммита, пуша и деплоя не было.

## 1. Редиректы `/en/*` → vibeui.club

**Было:** [proxy.ts](../../../proxy.ts) отдавал 404 на `/en` и `/en/*` на обоих доменах.
**Стало:** 301 на `https://vibeui.club/<путь без /en>`.
- Query сохраняется.
- Слитая категория ведёт сразу на родителя, без второго прыжка.
- Раздел не из `CLUB_SECTIONS` — по-прежнему 404 (`/en/legal/*`, `/en/foo`).
- `?ref=` обрабатывается раньше и, как и прежде, ведёт на `/i/<код>`.

Изменённые файлы:
- [lib/club-routes.ts](../../../lib/club-routes.ts) — новый. `MERGED_CATEGORIES` и `CLUB_SECTIONS` вынесены из `next.config.ts` без изменений, плюс `CLUB_ORIGIN`. Это лёгкий модуль: proxy не может импортировать `lib/seo.ts`, тот тянет весь registry.
- [next.config.ts](../../../next.config.ts) — импортирует их оттуда; поведение rewrites и redirects прежнее.
- [lib/seo.ts](../../../lib/seo.ts) — `CLUB_ORIGIN` реэкспортирует из club-routes.
- [proxy.ts](../../../proxy.ts) — функция `clubPathFor` и сам 301.

Проверки (без сборки):
- Синтаксис 13 изменённых файлов через `typescript.transpileModule` — 0 ошибок. Типы не проверялись (tsc запрещён), их поймает CI.
- Прогон скомпилированного `proxy()` на `NextRequest` для обоих хостов:
  - `/en` → `/`;
  - `/en/components/navigation-menu` → `/components/navigation` (слитая);
  - `/en/blocks/bakery` → `/blocks/industry`;
  - `/en/animations/text` → `/animations/promo`;
  - `/en/pricing?utm_source=x&plan=yearly` → query сохранён;
  - `/en/legal/offer` → 404;
  - `/en?ref=abc` → 307 `/i/abc`;
  - `/enx` и `/components` не затронуты.
- 374 реальных 404-адреса из GSC: все дают 301. Из 368 уникальных целей на production .club 359 отвечают 200, 9 — 404. Это удалённые items (`blocks/ai-005`, `auth-016`, `dashboard-031`, `dashboard-047`, `features-001`, `components/avatar-033`, `textarea-001`), категория `textarea` и сценарий `service-landing`. Для них — честный 404 за один прыжок.
- Петель нет: цель никогда не начинается с `/en`. Цепочек нет: слитые категории разрешаются в proxy сразу, а цели проверены — сами не редиректят.
- Смоук [deploy.yml](../../../.github/workflows/deploy.yml) проверял `/en/start` = 404 на обоих доменах. Синхронизировал по правилу проекта: теперь ожидается `Location: https://vibeui.club/start`. Без этой правки job упал бы после деплоя.
- После деплоя вручную: `curl -I https://vibeui.ru/en/components/accordion` → 301.

## 2. События аналитики

Модуль [lib/track.ts](../../../lib/track.ts): `track(name, params, done?)` шлёт GA4 `event` и Метрике `reachGoal` под одним именем. ID счётчиков перенесены туда, [components/analytics.tsx](../../../components/analytics.tsx) импортирует их оттуда.

|---|---|---|---|
| `copy_for_ai` | после успешного `navigator.clipboard.writeText` подписанной ссылки. Отказ сервера (лимит, нет Pro) и ошибка буфера — не считаются | [copy-for-ai.tsx](../../../components/catalog/copy-for-ai.tsx), [scenario-copy.tsx](../../../components/catalog/scenario-copy.tsx) | item, source (`item`/`scenario`), theme, locale |
| `sign_up` | `authClient.signUp.email` вернул ответ без ошибки — аккаунт создан, письмо подтверждения ушло. Ошибки 422/429 и сбой сети не считаются | [flip-auth.tsx](../../../components/auth/flip-auth.tsx) | method `email`, locale |
| `begin_checkout` | касса создала платёж (ЮKassa) или инвойс (NOWPayments). Server action вместо прямого `redirect(url)` ведёт на [/checkout/go](../../../app/checkout/go/page.tsx). Страница шлёт событие, ждёт подтверждения от GA4 и Метрики до 1,5 с и уходит в кассу через `location.replace`. Касса не настроена или не ответила — путь прежний, события нет | [lib/payment-actions.ts](../../../lib/payment-actions.ts), [lib/checkout-handoff.ts](../../../lib/checkout-handoff.ts), [components/checkout-go.tsx](../../../components/checkout-go.tsx) | plan, value, currency |

Защита `/checkout/go`:
- `to` принимается только `https://` на `yoomoney.ru`, `yookassa.ru`, `nowpayments.io` и их поддоменах, иначе редирект на `/pricing`. Тест: 9 случаев, включая `yoomoney.ru.evil.com`, `http:` и `javascript:` — все отсечены.
- Страница закрыта `noindex, nofollow`.

Компонент `SignupForm` не используется нигде, событие в него не добавлено.

**Риск, проверить до релиза.** Хосты кассы взяты из документации провайдеров, а не из реальных ответов. Если `confirmation_url` ЮKassa придёт с другого хоста, оплата уйдёт на `/pricing`. Нужен один тестовый платёж на staging или локально с тестовым магазином ЮKassa.

Dev-режим (React StrictMode) может отправить `begin_checkout` дважды. В production это не так.

**page_view:**
- В GA4 включена улучшенная статистика «Просмотры страниц» (видно в настройках потока).
- На SPA-переход `/blocks` → `/blocks/hero` в сети один запрос с `en=page_view` в URL.
- Тело POST не проверено: перехват не сработал, а у GA4 в одном пакете бывает несколько событий.
- Итог: **дубль не подтверждён и не опровергнут.** Проверить в GA4 DebugView. Кода я не менял.

Попутно: запросы GA4 `collect` из браузера пользователя вернули **503** — см. SEARCH-DATA.

**Отдельная задача (не делалась):** серверный `purchase` из вебхуков `app/api/payments/webhook` и `.../nowpayments/webhook`. Варианты — GA4 Measurement Protocol (нужен API secret) и офлайн-конверсии Метрики.
