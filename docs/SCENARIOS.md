# SCENARIOS — готовые страницы из блоков

## Зачем

«Компоненты / Блоки / Анимации» описывают, **из чего собрана библиотека**.
Человек приходит с другим: «делаю сайт фотографа». Сценарий отвечает готовой
страницей: вот результат целиком, вот из каких блоков он собран, вот одна
ссылка агенту — и такая же страница появляется в его проекте.

Вариантов сценарий не предлагает. Это не конструктор: мы показываем, что
использовали, и отдаём рецепт.

## Чем сценарий не является

`registry/categories.ts` объявляет `kind: "template"` — «Шаблоны». Это
готовая страница **одним item'ом**, которая устанавливается целиком.

Сценарий — не шаблон. Он ничего не устанавливает и не публикуется в
реестре. Ставятся сами блоки, своими обычными командами; страница собирается
агентом по исходнику демо.

## Где что лежит

| Файл | Что |
| --- | --- |
| `registry/scenarios.ts` | данные: слаг, тексты, путь демо и исходника, тема, секции с ролями |
| `app/scenarios/<slug>/demo/page.tsx` | демо-страница — **источник правды** для рецепта и брифа |
| `docs/scenarios/<slug>/IMAGES.md` | промпты картинок демо (таблица «файл · формат · промпт») |
| `lib/scenario.ts` | секции с живыми items из каталога, имя для подписи |
| `lib/scenario.server.ts` | чтение исходника, вырезка примеров, промпты картинок, бриф |
| `app/scenarios/[slug]/page.tsx`, `/en/…` | страница рецепта |
| `app/s/[slug]/route.ts` | бриф агенту по подписанной ссылке |
| `app/api/scenario-link/route.ts` | выдача подписи кнопке (только Pro) |
| `components/pages/scenarios-page.tsx`, `scenario-page.tsx` | витрина и рецепт |

## Устройство сценария

```ts
{
  slug: "photographer",
  label: "Портфолио фотографа",
  en: "Photographer portfolio",
  summary: "…", summaryEn: "…",
  demo: "/scenarios/photographer/demo",
  source: "app/scenarios/photographer/demo/page.tsx",
  sourceEn: "app/en/scenarios/photographer/demo/page.tsx", // если есть английское демо
  images: "docs/scenarios/photographer/IMAGES.md",
  theme: { tone: "light", accent: "#c2410c", ink: "#1c1917", font: "Neucha, Caveat" },
  sections: [
    { item: "sketch-019", role: "Шапка", roleEn: "Header", note: "…", noteEn: "…" },
  ],
}
```

## Английское демо

Русский текст блоков — их дефолтные props, поэтому русское демо почти ничего
не передаёт. Английская версия — отдельная страница
`app/en/scenarios/<slug>/demo/page.tsx` с тем же составом и темой, где весь
видимый текст передан в props (`const navbar: Navbar028Props = {…}` и
`{...navbar}` в JSX). Она регистрируется полем `sourceEn`, и тогда:

- на `/en/scenarios` карточка и кнопка «Open the demo» ведут на
  `/en/scenarios/<slug>/demo`, постер берётся из
  `public/demo/scenarios/en/<slug>.webp`
  (`node scripts/scenario-covers.mjs <base> --en <slug>`);
- бриф для агента на английской витрине собирается из английского исходника;
- в sitemap у демо появляется языковая пара.

Без `sourceEn` английская витрина показывает русское демо. Строки, зашитые
в блоке помимо props (единицы, aria, форматы вроде «через {n} мин»), перед
переводом выносятся в props с русским дефолтом — так блок не меняется для
тех, кто его уже скачал.

`sections` — **конкретные items**, в порядке появления на странице. Роль на
странице — половина ценности: «Первый экран», а не «sketch-016». Имена
проверяются при загрузке модуля: опечатка роняет сборку.

Всё, что можно вывести из исходника, из него и выводится: пример
использования каждого блока (`extractUsage` по `meta.ai.export`), состав
импортов, картинки. Правило: **не описывать в данных то, что уже написано в
демо-странице.**

## Кто что видит

- Все: демо в живом кадре, список блоков со ссылками в каталог — видно, что
  каждый блок есть на сайте.
- Pro: JSX каждого блока как в демо, общие правила темы, промпты картинок,
  кнопка «Копировать сценарий для ИИ».

## Бриф агенту

`/s/<slug>?exp&sig` (подпись на сутки, выдаётся только Pro) отдаёт
`text/plain`: правила, команду установки на каждый блок с подписанным
адресом, роли блоков и **исходник демо-страницы целиком** с импортами,
переписанными на `@/components/vibeui/<name>`, и картинками как
`/photos/*.webp`. Композиция — это код; лучшей инструкции «как собрать такую
страницу» нет.

## Новый сценарий — чек-лист

- [ ] демо-страница в `app/scenarios/<slug>/demo/page.tsx`: импорты только из
      `@/registry/...`, картинки в `public/demo/<slug>/`, одна тема на все блоки;
- [ ] `docs/scenarios/<slug>/IMAGES.md` с таблицей промптов;
- [ ] запись в `registry/scenarios.ts`: секции по порядку, у каждой роль;
- [ ] `npm run meta:validate`; глазами `/scenarios`, `/scenarios/<slug>` без
      Pro и с Pro, `/s/<slug>` по подписи — бриф с командами и исходником;
- [ ] `/scenarios/<slug>/demo` в sitemap появляется сам.

## Чего делать нельзя

- **Публиковать сценарий в реестре.** Он не item: ставить нечего.
- **Давать выбор внутри сценария.** Альтернатива — другой сценарий.
- **Дублировать в данных то, что есть в демо.** Разойдутся.
