# План: блоки сценариев → нейтральный стандарт каталога

Дата: 17 сентября 2026. Статус: выполнено 18 сентября 2026 по «безопасному» варианту (см. «Что сделано»).

## Как понята задача

Сценарии строились «сайт → потом блоки»: каждый блок родился внутри
демо-страницы и унаследовал её палитру как **умолчание**. Демо-страницы
цвета не передают — только `tone`: `const realty = { tone: "light" }`.
В итоге `realty-006` в каталоге сам по себе песочно-зелёный с латунью,
`navbar-021` — винный на тёмном, `hero-022` — индиго и т. д.

По замыслу должно быть наоборот: блок в каталоге выглядит как любой блок
VibeUI (чернильная палитра, см. `docs/PLAN-COLOR-CHANGE.md`), а сценарий
**перекрашивает** его пропсами. Тогда JSX в рецепте сценария честно
показывает, *чем именно* блок приведён к сайту.

Итог трёх правок на каждый блок:

1. умолчание палитры блока → нейтральное (как у `navbar-010`):
   `bg light-dark(#fff,#1a1a1a)`-класс, `fg light-dark(#1a1a1a,#f2f2f2)`,
   `accent light-dark(#1a1a1a,#f2f2f2)`, `on-accent` формулой;
2. пропсы для полной перекраски: сейчас у всех есть `tone`, `accent`,
   `background`; **нет `ink`** (цвет текста/заголовков) — а именно он даёт
   «чернильно-зелёный» realty, «сливовый» wedding, «морской» wedding-cuba.
   `ink` есть только в 7 блоках festival. Его нужно добавить в остальные
   ~90, иначе сценарий цветами пропсов не собрать;
3. демо-страница передаёт тему целиком:
   `const realty = { tone: "light", accent: "#b8925a", ink: "#173b2e", background: "#f3ede3" }`.
   `extractUsage` покажет `{...realty}` в JSX — рецепт увидит spread, а не
   значения. Значит, либо в блоке рецепта показывать рядом объект темы
   (одна правка `scenario-page.tsx`), либо в демо писать пропсы явно в
   каждом теге (шумно, ~12 повторов на страницу). Предпочтительно первое.

## Стандарт «как на сайте»

Эталон — любой блок вне сценариев после чернильной замены 12 сентября:

| Токен | Значение |
|---|---|
| bg | `light-dark(#ffffff,#1a1a1a)` (или `#f2f1ef`/`#000` для «сцен») |
| fg / ink | `light-dark(#1a1a1a,#f2f2f2)` |
| accent | `light-dark(#1a1a1a,#f2f2f2)` |
| on-accent | `oklch(from var(--accent) clamp(0,(0.62 - l) * 100,1) 0 0)` |
| muted, line, card | `color-mix` от fg/bg |
| font | `ui-sans-serif,system-ui,…` |

Открытый вопрос — **шрифты**. Все 97 блоков подключают Google Fonts
(Cormorant, Playfair, Unbounded, Oswald, Lobster, Marck Script…). Это
часть характера блока, а не цвета сценария. Варианты:

- А. Оставить шрифты как есть, менять только цвета. Дёшево, `realty-006`
  перестанет быть зелёным, но останется серифным.
- Б. Шрифт тоже к системному по умолчанию + проп `font`/`display`;
  сценарий передаёт свои. Правильнее по замыслу, но ×2 объём и часть
  блоков (hero-021 с тикером Playfair, hero-024 Unbounded) визуально
  потеряет смысл в каталоге.

Рекомендация: А сейчас, Б — отдельным решением после просмотра результата.

## Что не трогаем

  целевой образец.
- `background-006` (wedding-winter) — анимация фона, палитры сценария не
  несёт.

Особые случаи:

- **tattoo** и часть restaurant/winter — палитра без `light-dark()`,
  блок «тёмный по замыслу». Нейтрализация = добавить светлую ветку, иначе
  в каталоге на светлой подложке блок останется чёрным.
- **footer-019/024/025/026, realty-005** — инверсные секции (тёмная плита
  на светлой странице). Нейтральное умолчание: `bg = fg` страницы, как у
  обычных подвалов каталога.
- **navbar-025/026/027, navbar-024** — полупрозрачный `background` с
  `rgb(… / .85)`; проп `background` принимает цвет, альфу придётся
  сохранять внутри через `color-mix`.
- **festival** — лаймовый акцент с тёмным текстом на нём; после ink-акцента
  `on-accent` должен считаться формулой, а не литералом (проверить все 12).

## Сопутствующее

- `registry.json` каждого блока: `docs`, `ai.summary/preserve/adapt` и
  `i18n.en` упоминают цвета сценария («песок/чернильно-зелёный, латунный
  акцент», «wine-red glow»). ~97 × 2 языка правок текста + `ai.preserve`,
  где цвет назван «сохранить».
- `ai.usage` в metadata — пример без цветов, менять не нужно.
- `lib/scenario.server.ts` (бриф агенту) уже пишет правило темы
  `tone/accent/ink`; после появления пропа `ink` оно станет буквально
  исполнимым. Проверить, что бриф отдаёт объект темы вместе с исходником.
- Витрина `/scenarios` и карточки блоков — превью рендерится живьём, кэша
  картинок нет, пересборка не нужна.
- `.github/workflows/deploy.yml` не трогает: маршруты и коды не меняются.

## Риски

- Демо-страницы должны выглядеть точь-в-точь как сейчас: пропсы задают 3
  цвета, а палитра блока строит 6–10 токенов формулами. Там, где
  `muted/line/card` были подобраны руками, формула от `ink/bg` даст чуть
  иной оттенок. Ловится только скриншотом до/после.
- `on-accent` литералом (`#14211b` в realty-006) на чернильном акценте
  станет невидимым — обязательна формула.

## Что сделано (18 сентября 2026)

Безопасный вариант: блок меняет только умолчания, демо передаёт те же
значения явно — страницы сценариев по построению не изменились.

- 98 блоков семи сценариев: `bg`/`fg`/`accent` → нейтральные
  (`light-dark(#ffffff,#1a1a1a)`, `light-dark(#1a1a1a,#f2f2f2)`), `on-accent`
  формулой, `muted`/`line`/`glow` пересчитаны от `var(--fg/--bg/--accent)`;
  добавлен проп `ink` (цвет текста) везде, где его не было. Tattoo не
  трогали (неон — цельный дизайн). Шрифты не трогали.
- Акцент на плите цвета `fg` (кнопка и число в realty-006, кнопка в cta-017):
  токен `plate-accent` — нейтральный акцент переворачивается по светлоте,
  цветной (chroma > 0.02) остаётся как есть.
- Демо-страницы: объект темы `{ tone, background, ink, accent }` и
  производные (`realtyDark`, `paper`, `sand`); wedding/cuba/winter
  дополнительно возвращают свои декоративные оттенки (слива заголовков,
  песочные плашки, ночная синева карточек) одним `<style>` на странице —
  в каталоге эти токены серые.
- Рецепт сценария (Pro): над списком блоков выводятся строки темы из
  исходника (`extractThemeConsts`), подпись `themeNote` ru/en.
- Metadata: предложение «Палитра --vibeui-X-*…» переписано на нейтральное,
  «винный/коралловый/латунный/терракотовый/золотой» → «акцентный», точечно
  «тёмно-зелёный/сливовый/ночной фон» → «тёмный». Ru + en.
- Проверка: слепки computed-цветов всех блоков в 7 демо до/после —
  расхождения только `on-accent` (кремовый/тёмно-зелёный текст на кнопке →
  белый/чёрный по формуле); контактные листы 98 превью в обеих темах;
  `meta:validate` зелёный (127 предупреждений — как до правок);
  transpile-проверка 92 tsx без ошибок. Билд не запускался.

Оставлено как есть (по решению «не трогать рискованное»): tattoo (13),
лаймовый маркер course, стикеры festival, море/солнце cuba, серебро/огонь
winter, шалфей/латунь wedding, плейсхолдеры фото песочного оттенка.
