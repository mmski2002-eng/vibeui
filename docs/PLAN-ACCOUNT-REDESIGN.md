## 1. Диагноз текущего кабинета

Функционально кабинет полный: 9 разделов пользователя, партнёрский раздел,
6 разделов админа, действия с подтверждением и журналом. Проблемы —
визуальные и «ощущенческие»:

1. **Всё одинаковое.** Каждая страница — `h1` + серые панели `rounded-2xl
   border bg-shell-panel` + списки `divide-y`. Обзор, тариф, сводка админа и
   список платежей не отличаются по характеру. Иерархии уровней нет: панель
   почти сливается с фоном (`0.17` на `0.115`).
2. **Цифры без контекста.** `Metric` — подпись и число. Нет тренда, нет
   сравнения с прошлым периодом (кроме выручки), нет графиков. Единственный
   график — `DayBars` на 24px высоты без осей и подписей.
3. **Нет движения.** Только `transition-colors`. Нет появления панелей, нет
   отклика нажатия, нет анимации чисел и шкал, нет `loading.tsx` (скелетон
   из прошлой итерации удалён), переключение разделов — белая вспышка.
4. **Партнёрский раздел беден.** Три числа и список. Нет конверсии, нет
   динамики переходов по дням, нет выручки от рефералов.
5. **Сводка админа — стена из 16 плиток** без порядка чтения: деньги, люди,
   поиск в одном потоке, всё одного веса.
6. **Оранжевый — на всём сразу**: акцентные цифры, статусы, ссылки, кнопки,
   ошибки. Семантических цветов (успех/внимание/ошибка) в токенах нет.
7. Мобильная навигация — раскрывающийся список, приемлемо; на desktop
   активный пункт — серая плашка без движения.

## 2. Принципы редизайна

- Не переписывать с нуля: оболочка, маршруты, серверные запросы, тексты и
  действия остаются. Меняется слой представления и добавляется слой данных
  «по дням».
- **Ноль новых зависимостей.** Графики — свои SVG на сервере (линия,
  область, столбцы, кольцо, воронка). Данных мало (≤ 90 точек), библиотека
  графиков не оправдана и тянет бандл.
- Server Components по умолчанию; клиентские — только count-up чисел,
  переключатели, действия. Анимации — CSS (`@keyframes`, `@starting-style`,
  `transition`), с `prefers-reduced-motion`.
- Бренд: чёрный / Oil Black `#1A1A1A` / белый / `#F2F2F2` / оранжевый
  `#FF5900`. Оранжевый — только на главном действии, активном пункте и
  линии графика. Статусы получают свои цвета.
- Один набор примитивов на три роли: пользователь, партнёр и админ
  собираются из тех же панелей, плиток и графиков — разное содержание,
  один язык.

## 3. Визуальная система

### 3.1. Токены (`app/globals.css`, блок `.catalog-shell`)

Добавить, не меняя существующие:

```
--shell-ok / --shell-ok-soft          зелёный: оплачен, активна, подтверждена
--shell-warn / --shell-warn-soft      янтарный: past_due, ожидает, лимит < 10
--shell-danger / --shell-danger-soft  красный: ошибка, заблокирован, отменён
--shell-panel-2                       второй уровень поверхности (вложенные карточки)
--shell-glow                          radial-gradient оранжевого 6–8% для hero-панели
--motion-fast: 140ms; --motion-base: 220ms; --motion-slow: 420ms
--ease-out: cubic-bezier(0.16, 1, 0.3, 1)
```

Светлая тема: фон `#F2F2F2`, панели белые, тени вместо рамок на первом
уровне (сейчас светлая тема — серые прямоугольники на белом).

### 3.2. Примитивы кабинета — `components/account/ui/`

| Компонент | Что делает |
| --- | --- |
| `Panel` | панель с вариантами `default / elevated / hero / danger`; hero — с мягким оранжевым свечением по углу |
| `PageHeader` | заголовок, лид, действия справа; заменяет дублированные `h1` на девяти страницах и `AdminHeading` |
| `StatTile` | подпись, число (count-up), дельта к прошлому периоду со стрелкой и цветом, опциональный sparkline |
| `Sparkline` | SVG-линия 0–90 точек, без осей, анимация `stroke-dashoffset` |
| `AreaChart` | линия + заливка градиентом, сетка, подписи дат по X, значения по Y, точки при наведении с `<title>` (нативная подсказка, без JS) |
| `Bars` | столбцы по дням с подписями, рост снизу (`transform: scaleY`) |
| `Ring` | кольцо прогресса (лимит копирований, доля подтверждённых); анимация `stroke-dashoffset` |
| `Funnel` | 3–4 ступени с процентами (переходы → регистрации → оплаты) |
| `StatusPill` | статусы платежа, подписки, обращения, пользователя — цвет по семантике, не «muted/accent» |
| `DataTable` | таблица со sticky-шапкой, строками-ссылками, подсветкой при наведении; заменяет `ul divide-y` в админке |
| `SegmentedControl` | переключатель периода / фильтра с плавно едущей «таблеткой» |
| `Reveal` | обёртка появления панелей снизу с задержкой по индексу (`--i`) |
| `CountUp` | клиентский счётчик числа при появлении в viewport, `IntersectionObserver`, уважает reduced-motion |
| `Skeleton` | `loading.tsx` для всех разделов: контуры панелей с shimmer |
| `EmptyState` | иллюстрация-иконка, текст, действие — единый вид пустых списков |

Все — Tailwind + `cn()`, без inline-стилей кроме динамических значений.

### 3.3. Движение

| Событие | Поведение |
| --- | --- |
| Загрузка раздела | панели появляются снизу на 8px с fade, шаг 40мс, `--motion-slow` |
| Переход между разделами | `loading.tsx`-скелетон + `View Transitions` (Next 16 `experimental.viewTransition`) — фейд содержимого, боковая колонка стоит; если экспериментальный флаг не примем — только скелетон |
| Активный пункт навигации | оранжевая вертикальная риска и фон плавно едут к новому пункту (`transition: transform`) |
| Кнопки | hover — сдвиг тона; press — `scale(0.98)`; загрузка — spinner внутри без изменения ширины; успех — галка на 1.2 с |
| Карточки | hover — рамка теплеет (`--shell-accent-line`), подъём 1px, тень |
| Числа | count-up 600мс при первом показе |
| Графики | линия «рисуется», столбцы растут, кольцо заполняется — один раз при появлении |
| Списки с фильтром | смена элементов через fade, не скачком |
| Уведомления действий | тост снизу-справа вместо строки текста под кнопкой |
| `prefers-reduced-motion` | всё выше отключается, состояния показываются сразу |

## 4. Разделы по ролям

### 4.1. Пользователь

**Обзор `/account`** — три зоны:

- Hero-панель: имя, тариф (StatusPill), кольцо лимита «87 из 100» с датой
  обнуления (Pro — «без лимита»), одна главная кнопка «В каталог»; для Pro —
  дата окончания периода и «Управлять».
- Ряд StatTile: взято компонентов в этом месяце (+sparkline по дням),
  избранное, всего за всё время, дней до продления/обнуления.
- «Продолжить работу» с живым превью — остаётся, получает hover-подъём;
  сохранённые — карточки; активность — `Bars` за 30 дней вместо списка.

**Избранное, история** — существующая логика; карточки и строки на новых
примитивах, EmptyState, скелетон, история получает полосу активности по
месяцам над списком.

**Тариф и оплата** — карточка тарифа как hero, шкала-таймлайн текущего
периода (начало → сегодня → списание), кнопки продления с новым откликом;
`past_due` — янтарная панель с попытками.

**Платежи** — DataTable: дата, сумма, статус, чек; сумма за год сверху.

**Подключение к проекту, безопасность, поддержка** — только примитивы,
логика нетронута. Сессии — как карточки устройств с иконкой ОС.

### 4.2. Партнёр `/account/referrals`

- Hero: ссылка с копированием (отклик «Скопировано» в кнопке), код крупно.
- Четыре StatTile: переходы, регистрации, оплаты, **конверсия %** — с дельтой
  к прошлому периоду.
- `AreaChart` переходов и регистраций за 30/90 дней (SegmentedControl).
- `Funnel` переходы → регистрации → оплаты.
- Список рефералов — DataTable со статусом и датой; маскировка почты остаётся.

Нужны новые запросы в `lib/partners.ts`: `visitsByDay(code, days)`,
`referralsByDay(userId, days)`, тоталы за прошлый период. Всё — `group by
date_trunc('day')`, с существующими индексами.

### 4.3. Администратор

**Сводка `/account/admin`** — порядок чтения сверху вниз:

1. Строка из 4 ключевых StatTile с дельтами и sparkline: выручка, новые Pro,
   регистрации, активные пользователи.
2. `AreaChart` выручки по дням + рядом `Bars` регистраций (два графика в ряд,
   на телефоне — столбиком).
3. Ряд «внимание»: зависшие платежи, неудачные списания, отмены — цветом
   `warn/danger`, каждая плитка — ссылка на отфильтрованный список.
4. Воронка: посетители по реф-ссылкам → регистрации → подтверждённые → Pro.
5. Поиск: топ запросов и пустые запросы — две колонки, как сейчас, на
   `Ranked` с полосой доли.

**Платежи, пользователи, обращения, партнёры, журнал** — DataTable со sticky
шапкой, фильтры в SegmentedControl, курсорная пагинация остаётся; строки
подсвечиваются, статусы — StatusPill по семантике.

**Карточка пользователя** — шапка с тарифом и статусом, таймлайн событий
(регистрация, подтверждение, платежи, действия админа) вместо разрозненных
панелей; опасные действия (блокировка, выход везде) — в `Panel variant=danger`.

**Карточка партнёра** — те же графики и воронка, что видит сам партнёр, плюс
выручка от его рефералов.

Новые запросы в `lib/admin-stats.ts`: `revenueByDay`, `usageByDay`,
сравнение всех метрик с предыдущим периодом (сейчас — только выручка),
воронка. Все — SQL-агрегаты, лимиты сверху, без выгрузки таблиц в память
(сервер общий, 2 ядра).

## 5. Этапы

Каждый этап — отдельный коммит-пакет, проверяемый глазами.

| # | Этап | Результат | Проверка |
| --- | --- | --- | --- |
| 0 | Проверка | локальная база на 5433 + `ADMIN_EMAILS` в `.env.local` (или проверять на проде после каждого этапа); для Pro и партнёра — выдать тестовому аккаунту Pro-дни и партнёрскую ссылку через админку | вход в кабинет в браузере |

| 2 | Пользователь | обзор, тариф, платежи, избранное, история, подключение, безопасность, поддержка | все 9 разделов, пустые состояния, Free и Pro |

по вашей команде, как по правилу проекта.
