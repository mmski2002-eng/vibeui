# План: категория «Раскладки» (`layout`)

Дата: 13 сентября 2026. Статус: реализовано 13 сентября 2026; в реестре 12 раскладок (`layout-001…010`, `012`, `014`) — L11 брутальная сетка, L13 устройства, L15 три панели и L16 документация удалены по решению владельца. Отличия от плана: L13 на фото-корпусах из `public/demo/devices` (проп `frames`), а не на CSS-рисунке; у всех раскладок общий каркас — номера слотов (`numbers`), свет за курсором, появление по `view()`; превью-страница получила `overflow-x-clip` вместо `hidden`, иначе `sticky` не работал.

## Зачем и чем отличается от прошлого

Прошлая категория `layout` (S01–S20 из [PLAN-SITE-FOUNDATIONS.md](PLAN-SITE-FOUNDATIONS.md) §6,
`layout-001…019`) удалена в `7f256174` как колхозная: это были каркасы-скелеты
«шапка + main + футер», без характера, без движения, на палитре, которой больше
нет. Пользователь их не выбирал глазами — выбирать было нечего.

Новая категория — **композиции**, а не каркасы. Раскладка здесь — то, как
контент собран в кадре и как он ведёт себя при прокрутке и наведении: bento,
стопка карточек, горизонтальная лента, кинетический заголовок. Каждая должна
быть узнаваема по миниатюре и продавать себя без текста, как фоны.

Что сейчас модно и уже стало стандартом (сентябрь 2026, источники внизу):

- **Bento** — асимметричные модульные плитки на общей сетке, «витрина Apple».
  Главный паттерн года; в 2026 плитки стали живыми: hover раскрывает,
  играет видео, показывает второй слой.
- **Редакционные и асимметричные сетки** — hero перестаёт быть «заголовок по
  центру + кнопка», становится композицией: типографика, ритм, воздух.
- **Стопки карточек и sticky-сцены** — секции наезжают друг на друга при
  прокрутке, картинка закреплена, текст идёт мимо (scrollytelling).
- **Кинетическая типографика как архитектура** — заголовок во весь вьюпорт
  держит раскладку вместо картинки.
- **Тактильный брутализм** — видимые линейки, рамки, моноширинные подписи,
  «инженерная» сетка вместо парящих карточек.
- **Оболочки приложений** — сайдбар + топбар + рабочая область; для SaaS и
  кабинетов это по-прежнему база.

## Что такое item категории

Раскладка — один блок `registry/blocks/layout/<name>/`, один файл, ноль
зависимостей, как фоны. Внутри:

- **Слоты, а не контент.** Блок принимает плитки/панели через `children` или
  массив `items` с полями `{ title?, text?, media?, span?, accent? }` и
  расставляет их. Без `children` рисует призрак — серые плашки и стеклянные
  карточки той же геометрии, как у фонов. Никаких зашитых текстов «Ваш заголовок».
- **Геометрия — CSS Grid и container queries.** Раскладка сворачивается по
  своей ширине, не по вьюпорту; порядок DOM = порядок чтения, `order` и
  визуальные перестановки не ломают Tab.
- **Движение — CSS-first.** Стопки, ленты, sticky-сцены на `position: sticky`
  и `animation-timeline: scroll()` / `view()` под `@supports`; без поддержки —
  статическая раскладка, а не пустота. JS только там, где без него никак
  (наведение с раскрытием, измерение). `prefers-reduced-motion` — статика.
- **Не второй scroll-root.** Раскладка живёт в потоке документа, не создаёт
  собственный `overflow: auto` на всю высоту (кроме app-shell, где владелец
  прокрутки объявлен явно в пропе и в Copy for AI).
- **Палитра** — та же схема, что у фонов: `--vibeui-<name>-*`, `light-dark`,
  `tone`, `accent`; плитки могут принимать `surface-*` из категории «Фон» как
  фон плитки — это и есть «bento с живыми плитками».
- **Превью** — `width: "natural"`, категория `wide: true`. Кадр каталога
  имеет внутренний `overflow-y: auto` (до 620px), поэтому скролл-сцены
  показываются прямо в карточке: `animation-timeline: scroll(nearest)`
  считает от кадра. Для скролл-раскладок `aspect` выше (1280 / 900),
  чтобы в кадре было что крутить.

## Семейства

Код `L`, приоритет: P1 — первая волна (8), P2 — вторая (6), P3 — по спросу.

| Код | Название | Что это | Движение | Настройки | P |
|---|---|---|---|---|---|
| L01 | **Bento-витрина** | 6–8 плиток разного размера на сетке 4×3, одна ведущая 2×2, плитки-статистика 1×1 | hover: плитка чуть поднимается, фон плитки оживает (`surface-*`) | `density` (6/8), `lead` (left/right), `radius` | P1 |
| L02 | **Bento-hero** | первый экран как bento: заголовок в большой плитке, кнопка, превью продукта, два доказательства | появление плиток каскадом при загрузке | `columns`, `media` слот под кадр/`surface` | P1 |
| L03 | **Редакционная сетка** | 12 колонок, ведущий материал 8/12, узкие заметки, линейки, номера разделов | нет; ритм — размерами | `rules` (on/off), `numbers`, `lead` | P1 |
| L04 | **Стопка карточек** | секции-карточки наезжают одна на другую при прокрутке, нижняя чуть уменьшается | `sticky` + `scroll()`: scale и затемнение | `gap`, `shrink`, `offset` под шапку | P1 |
| L05 | **Горизонтальная лента** | секция закрепляется, содержимое едет вбок по вертикальной прокрутке | `sticky` + `translateX` по `scroll()` | `panels` (3–6), `snap` | P1 |
| L06 | **Сцена с закреплённым медиа** | картинка/кадр закреплён слева, справа идут главы; кадр меняется по главе | `sticky` + `view()` для смены кадра | `side`, `media` слоты по главам | P1 |
| L07 | **Кинетический заголовок** | заголовок в масштаб вьюпорта держит кадр, контент — мелкими колонками по углам | буквы разъезжаются по прокрутке (`scroll()`), на hover — сдвиг веса | `word`, `weight`, `corners` | P1 |
| L08 | **Оболочка приложения** | сайдбар, топбар, рабочая область; сайдбар сворачивается | сворачивание сайдбара (CSS `:has` + чекбокс без JS) | `sidebar` (left/right), `collapsed`, `topbar` | P1 |
| L09 | **Раскрывающиеся панели** | 4–6 вертикальных панелей, наведённая расширяется, остальные сжимаются | `flex-grow` transition по hover/focus | `panels`, `expand` (hover/click) | P2 |
| L10 | **Мозаика** | плотная сетка плиток разной высоты (`grid-auto-flow: dense`) | появление при `view()` | `columns`, `dense` | P2 |
| L11 | **Брутальная сетка** | видимые рамки всех ячеек, моноширинные подписи-координаты, «чертёж» | нет | `lines` (thin/thick), `labels` | P2 |
| L12 | **Орбита интеграций** | центр + элементы по кольцам, соединённые линиями; для «работает с» | медленное вращение колец, пауза на hover | `rings` (1/2), `count`, `spin` | P2 |
| L13 | **Витрина в устройствах** | композиция из ноутбука, телефона, планшета с экранами-слотами (рамки уже есть в `public/demo/devices`) | лёгкий параллакс слоёв за мышью | `set` (laptop+phone / phone+tablet / trio) | P2 |
| L14 | **Таймлайн с закреплённым годом** | слева год/этап sticky, справа события | `sticky` на группу | `side`, `marker` | P2 |
| L15 | **Три панели** | список / объект / детали, как почта и чат | нет; на телефоне — последовательные экраны | `weights`, `dividers` | P3 |
| L16 | **Документация** | дерево / текст / оглавление, sticky-колонки | активная глава по `scrollspy` (есть в реестре) | `toc` (on/off), `width` | P3 |

Что сознательно не входит: бегущие ленты (это контент-секция), полноэкранный
scroll-snap «fullpage» (ломает прокрутку и доступность, в 2026 считается
антипаттерном), бесконечная лента (нет у неё футера), «шапка + main + футер»
без характера (было, удалено).

## Контракт для Copy for AI (пишется один раз)

- идентификатор, команда установки, ноль зависимостей;
- сохранить: порядок DOM как порядок чтения, container-запросы, статику при
  `reduced-motion` и без `animation-timeline`, отсутствие второго scroll-root;
- адаптировать: слоты (`items`/`children`), `accent`, `tone`, семейные пропы,
  фон плиток (`surface-*`);
- запрет: не пересобирать раскладку «своими div», не заменять sticky-сцену на
  JS-скролл-хайджек, не превращать bento в равные карточки.

## Порядок работы

1. Категория: запись в `registry/categories.ts` (`slug: "layout"`,
   `label: "Раскладки"`, `group: "marketing"`, `wide: true`), `SYNONYMS`
   (`bento, grid, layout, stack, sticky, horizontal scroll, editorial, app shell,
   sidebar, masonry, timeline, orbit`), шаг в сценариях
   ([SCENARIOS.md](SCENARIOS.md)) — раскладка идёт после hero в «лендинге».
2. Каркас-генератор, как у фонов: общая палитра, призрак, controls, i18n;
   семейство добавляет только CSS/разметку. Скролл-раскладки — общий кусок
   `@supports (animation-timeline: scroll())` + статический фолбэк.
3. Первая волна L01–L08, по одному: `npm run item -- layout`, `meta:validate`,
   глаза на 1280/768/390 и в обеих темах, проверка в карточке каталога, что
   скролл-сцена крутится внутри кадра.
4. Вторая волна L09–L14. L15–L16 — когда попросят.
5. Отчёт в `docs/` после каждой волны.

## Риски

- `animation-timeline` есть в Chrome/Edge/Safari 26, в Firefox — за флагом.
  Фолбэк статический, это принятое решение, не баг.
- Bento с `surface-*` внутри плиток — несколько WebGL-контекстов на странице.
  Лимит браузера ~16; в призраке живой фон только у ведущей плитки.
- Слабая машина: сцены на `sticky` + `transform` дешёвые, но L13 (параллакс за
  мышью) и L12 (вращение) — через `transform` только, без `filter`.
