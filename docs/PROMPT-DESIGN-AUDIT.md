# Промпт: аудит дизайна, UX и анимаций VibeUI

Скопировать целиком в новую сессию Claude Code в корне `C:\VIBEUI`.

---

Ты — senior product designer + frontend-инженер. Задача: провести подробный аудит
сайта VibeUI (Next.js 16, Tailwind v4, tw-animate-css) с точки зрения дизайна,
удобства, современности, красоты и «живости» — переходов, откликов на действия,
анимаций. Результат — конкретный, применимый план улучшений.

## Режим работы

- Только анализ. Код, конфиги, базу, деплой не менять.
- Перед началом прочитай `CLAUDE.md`, `docs/PROJECT_CONTEXT.md`, `docs/PRODUCT.md`.
  Бренд — `BREND.jfif` в корне (открой как картинку), токены и вся анимация —
  `app/globals.css` (`--motion-*`, `--ease-*`, `view-transition`, `@media
  (prefers-reduced-motion)`).
- Запрещено: `npm run build`, `lint`, `typecheck`, `tsc`, `eslint`. Только
  `npm run dev` и браузер.
- Машина слабая (2 ядра). Один dev-сервер, после проверок погасить. Браузер
  (Playwright) закрывать, когда не работаешь с ним. Субагентов не плодить —
  максимум один-два `Explore` для быстрого чтения кода, всё остальное сам.
- Не выдавай прочитанное за факт: каждое утверждение о поведении интерфейса
  подтверди либо строкой кода (`файл:строка`), либо наблюдением в браузере.
- Уже есть продуктовый список доработок `АНАЛИЗ ДИЗАЙНА.md` (сценарий
  «сайт-каталог», раздел «Галерея», примерка цвета, скелетоны). Не дублируй его —
  ссылайся, если пересекается. Твой фокус — визуал, ощущение от интерфейса,
  моушен.

## Что смотреть

Пройти в браузере на трёх ширинах (390 / 820 / 1440) и в обеих темах
(`theme-switch`):

1. `/` — лендинг. Первый экран, hero, обещание «Выбери дизайн → отдай ИИ →
   получи сайт», CTA, появление секций при скролле.
2. `/components` — каталог: сайдбар, топбар, сетка карточек, hover карточки,
   lazy-загрузка превью (`components/catalog/lazy-thumbnail.tsx`,
   `live-cover.tsx`), пустые состояния, `favorites`.
3. `/components/<slug>` любой категории (например `cards`, `hero`) — страница
   категории и переход в неё из каталога.
4. Страница item'а (`/components/<category>/<name>` или как резолвится в
   `components/pages/item-page.tsx`): workbench, конфигуратор
   (`item-configurator.tsx`), переключение подложки/устройства
   (`device-frames.tsx`), `Copy for AI` (`copy-for-ai.tsx`, `copy-flow.tsx`,
   тост, `gated-reveal.tsx` для анонима), `code-sheet.tsx`.
5. `/search?q=карточка` и `search-box.tsx` — подсказки, ввод, пустая выдача.
6. `/scenarios`, `/scenarios/<slug>`, `/scenarios/<slug>/demo` — `scenario-tour.tsx`.
7. `/blocks`, `/animations` — отдельные разделы, единообразие с `/components`.
8. `/pricing`, `/signin`, `/signup`, `/account` — формы, состояния загрузки и
   ошибок, тосты (`acc-toast-in`), view-transition (`.acc-page`).
9. `/not-found` — 404.

Для каждой страницы оценить:

- **Визуал**: иерархия, типографика (размеры, межстрочные, длина строки),
  spacing и ритм, цвет и контраст, соответствие бренду, тёмная тема (не
  «инверсия», а продуманная), качество карточек и рамок, пустоты и тесноты.
- **UX**: понятно ли с первого экрана, что делать; сколько кликов до
  `Copy for AI`; читаемость навигации; состояния (пусто / загрузка / ошибка /
  успех); обратная связь на каждое действие; фокус и клавиатура; тексты кнопок.
- **Моушен**: что анимировано, а что «прыгает» без перехода; hover/active/focus
  на кнопках, карточках, ссылках; появление контента (скелетон vs белый ящик);
  переходы между страницами (`view-transition`); тосты; открытие панелей и
  шторок; длительности и кривые против `--motion-*`; согласованность
  (одинаковые вещи двигаются одинаково); `prefers-reduced-motion`; нет ли
  перебора и дёрганья (layout shift, mount-анимации при каждом ре-рендере).
- **Современность**: как выглядит рядом с shadcn/ui, 21st.dev, Magic UI,
  Aceternity, uiverse. Что выглядит устаревшим или «дефолтным Tailwind».
- **Адаптив**: 390px — ничего не вылезает, тап-зоны ≥ 44px, сайдбар/фильтры
  на мобиле, шрифты не меньше 14px в тексте.
- **Воспринимаемая скорость**: что появляется первым, что мигает, где
  пользователь ждёт без индикации.

## Формат результата

Записать в новый файл `docs/DESIGN-AUDIT.md`. В чат — только две строки:
путь и число находок. Структура файла:

```
# Аудит дизайна и моушена VibeUI — <дата>

## Резюме
5–8 предложений: общее впечатление, три главные проблемы, три сильные стороны.

## Оценки
Таблица: область (визуал / UX / моушен / адаптив / тёмная тема / a11y) →
оценка 1–10 → одна фраза почему.

## Находки
Сгруппировать по страницам. Каждая находка:

### <N>. <короткое название>
- Где: маршрут + файл:строка.
- Что не так: факт, как наблюдается (ширина, тема).
- Почему важно: влияние на пользователя / на сценарий «выбрать → скопировать».
- Что сделать: конкретно — какие классы, токены, компоненты, какие значения
  длительности/кривой, какой паттерн. Если предлагаешь библиотеку — только
  зрелую с GitHub/npm, с обоснованием, почему CSS/tw-animate-css не хватает.
- Сложность: S / M / L.
- Приоритет: P0 / P1 / P2.

## Система моушена (предложение)
Единые правила: длительности, кривые, что анимируем на hover / press / появлении
/ переходе страницы / в тостах; что запрещено. Опираться на существующие
`--motion-fast/base/slow` и `--ease-*` из `app/globals.css`, предложить
недостающее. Показать 3–5 CSS-фрагментов «было → стало».

## Быстрые победы
До 10 пунктов, каждый ≤ 1 часа работы, с указанием файла.

## План внедрения
Три волны (неделя каждая): что в какой, зависимости между пунктами.

## Что не трогать
Что уже хорошо и должно остаться как есть.
```

Требования к содержанию:

- Минимум 25 находок, из них не меньше 10 про моушен и отклики.
- Никаких общих фраз («улучшить UX», «сделать современнее») — только
  проверяемые предложения с конкретными значениями.
- Не предлагать переписывание проекта, смену стека, новые зависимости без
  явной необходимости; не предлагать marketplace, MCP, visual builder.
- Не предлагать менять registry-блоки (`registry/blocks/**`) — только сайт.
- Скриншоты сохранять не в корень и не в `docs/`, а в
  `C:\Users\Escape\AppData\Local\Temp\claude\` (в отчёт — словесное описание,
  не картинки).
- Язык отчёта — русский.
