# Аудит дизайна и моушена VibeUI — 2026-09-16

Аудит только сайта (не registry-блоков). Проверено в браузере на 390 / 820 / 1440
и в обеих темах, каждое утверждение подтверждено строкой кода или наблюдением.
Продуктовый список `АНАЛИЗ ДИЗАЙНА.md` (сценарий «сайт-каталог», «Галерея»,
примерка цвета, скелетоны) не дублируется — где пересекается, есть ссылка.

## Резюме

Сайт уже выглядит как продукт, а не как developer demo: тёмная оболочка держит
бренд FNATIC (чёрный / Porcelain / оранжевый #FF5900), типографическая шкала
`type-display…type-label` даёт крупному кеглю тесный трекинг, светлая тема
продумана (Porcelain-фон + белые панели, а не инверсия), а лендинг, страница
сценария и 404 сделаны на уровне 21st.dev. Три главные проблемы. Первое —
**моушен есть в кабинете и на входе, но отсутствует в самом каталоге**: карточки
на hover только меняют цвет рамки (`transition-colors`), превью грузятся чёрным
прямоугольником без скелетона по 4–5 секунд, переключение устройства и режима
сетки происходит скачком. Второе — **система движения расколота**: кабинет живёт
на `--motion-*` + `--ease-out`, а весь остальной сайт — на дефолтной кривой
Tailwind `cubic-bezier(0.4,0,0.2,1)` и хардкоде `duration-500/700`, `#ff7a33`.
Третье — **аноним не видит главного действия**: на карточке и на странице item
`Copy for AI` заменён кнопкой «Войти», то есть путь «выбрал → скопировал» для
неавторизованного обрывается в ноль. Сильные стороны: продуманная светлая тема,
цельная брендовая палитра оболочки, зрелые точечные анимации (`code-sheet`,
`acc-*`, `auth-*`, `hero-rise`).

## Находки

### Лендинг `/`

#### 1. Летающие фото-тайлы в hero статичны
- Где: `/`, `components/pages/landing-page.tsx` (hero, слой декоративных тайлов за заголовком).
- Что не так: 1440/тёмная — за заголовком разбросаны карточки-фото под наклоном,
  они выглядят как заготовка под параллакс/дрейф, но не двигаются вообще: ни на
  скролл, ни на курсор. Статичная «россыпь» читается как то, что анимация не
  доехала.
- Почему важно: это первый экран и главное обещание; замерший коллаж снижает
  ощущение «живого» продукта, ради которого этот аудит.
- Что сделать: дать тайлам очень медленный ambient-дрейф по образцу
  `auth-drift-a/b` (`app/globals.css:1131`) — `translate` ±6–10px + `scale`
  0.98–1.02, длительность 16–24s, `ease-in-out`, у каждого свой `animation-delay`;
  обязательно `@media (prefers-reduced-motion: reduce) { animation: none }`. Либо
  лёгкий parallax на `scroll` через `translateY(calc(var(--sy) * k))`. Без новых
  зависимостей.
- Сложность: M. Приоритет: P2.

#### 2. Кривая hover не совпадает с фирменной `--ease-out`
- Где: весь сайт; примеры `components/pages/landing/category-explorer.tsx:50`,
  `components/catalog/catalog-nav.tsx` (класс `catalog-nav-item`),
  `components/catalog/theme-switch.tsx:86`.
- Что не так: почти все интерактивные элементы используют `transition-colors`,
  который в Tailwind v4 разворачивается в `…0.15s cubic-bezier(0.4,0,0.2,1)`
  (проверено `getComputedStyle`: `transitionTimingFunction` navItem/topbarLink =
  `cubic-bezier(0.4, 0, 0.2, 1)`). При этом проект объявил свою кривую
  `--ease-out: cubic-bezier(0.16,1,0.3,1)` (`app/globals.css:70`), но она живёт
  только в кабинете (`acc-*`). Сайт и кабинет двигаются по-разному.
- Почему важно: согласованность моушена — половина ощущения качества; две разные
  кривые на одинаковых действиях читаются подсознательно как «разные команды делали».
- Что сделать: ввести утилитарный класс, например `.ui-trans` в слое `components`:
  `transition: color, background-color, border-color, box-shadow var(--motion-fast) var(--ease-out)`
  и заменить им «голый» `transition-colors` на ключевых элементах (кнопки, ссылки,
  карточки). Значения: hover/press = `--motion-fast` (140ms), появление =
  `--motion-base` (220ms). См. раздел «Система моушена».
- Сложность: M. Приоритет: P1.

#### 3. Нет перехода между страницами сайта
- Где: переходы `/` ↔ `/components` ↔ `/components/<slug>`; `view-transition`
  объявлен только для кабинета — `::view-transition-*(.acc-page)` (`app/globals.css:1314`).
- Что не так: навигация по каталогу — жёсткая смена кадра без затухания. Кабинет
  же плавно сменяет рабочую область (`.acc-page`). Разный класс перехода на
  соседних разделах одного продукта.
- Почему важно: плавный переход между каталогом и страницей item прямо
  поддерживает сценарий «просматриваю → проваливаюсь в компонент → назад».
- Что сделать: назначить общий `view-transition-name` контейнеру контента
  каталожных страниц и добавить пару правил по образцу `.acc-page`
  (`::view-transition-old/new` с `acc-fade`, 120/220ms). Next.js 16 App Router
  поддерживает MPA-переходы; включить только при `not (prefers-reduced-motion)`.
- Сложность: M. Приоритет: P2.

### Каталог `/components`, `/blocks`, `/animations`

#### 4. Карточка на hover меняет только цвет рамки
- Где: `components/catalog/catalog-card.tsx:38` — `article.catalog-card …
  hover:border-shell-accent-line … transition-colors`.
- Что не так: наведение на карточку меняет лишь рамку на тёплую. Ни подъёма, ни
  тени, ни отклика превью. При этом в кабинете уже есть готовый паттерн `.acc-lift`
  (`translateY(-2px)` + тёплая рамка + `box-shadow`, `app/globals.css:1256`),
  который здесь не задействован.
- Почему важно: карточка — главный кликабельный объект каталога; слабый отклик
  делает сетку «неживой» и не подсказывает кликабельность.
- Что сделать: добавить карточке класс уровня `.acc-lift` — на hover
  `transform: translateY(-2px)` + `box-shadow: var(--shell-shadow)` + тёплая рамка,
  `transition … var(--motion-base) var(--ease-out)`. Обязательно
  `prefers-reduced-motion` (уже гасит `.acc-lift`). Не задевать сам кадр превью
  (`transform` на карточке, не на `.block-thumbnail-scale`).
- Сложность: S. Приоритет: P1.

#### 5. Превью грузятся чёрным ящиком без скелетона
- Где: `/search?q=…` и глубокий скролл `/components`; `components/catalog/lazy-thumbnail.tsx:108`
  (IntersectionObserver, `rootMargin: "800px 0px"`), появление — `.preview-fade`
  (`app/globals.css:759`, `opacity 0.45s`).
- Что не так: наблюдение — на `/search?q=карточка` кадры висят сплошным чёрным
  прямоугольником ~4–5с, пока не приедет чанк компонента, и лишь потом проступают
  (`preview-fade` — только `opacity`, скелетона под ним нет). В тёмной оболочке это
  ровно тот «чёрный ящик», о котором п.6 `АНАЛИЗ ДИЗАЙНА.md` — но там про белые
  ящики; здесь фиксирую именно моушен-сторону: под fade ничего не мерцает.
- Почему важно: воспринимаемая скорость; на слабой машине (i5-6200U) ожидание
  без индикации читается как «сломалось». Прямо бьёт по первому впечатлению в
  выдаче поиска.
- Что сделать: в каркасе кадра (`.preview-frame` до вставки чанка) показывать
  `.acc-skeleton` — он уже есть в проекте (`app/globals.css:1295`, shimmer 1.4s,
  гасится `prefers-reduced-motion`). Скелетон рендерить как fallback до
  срабатывания observer/загрузки чанка, снимать в `preview-fade`. Пересекается с
  `АНАЛИЗ ДИЗАЙНА.md` п.6 — там же предложено начинать загрузку раньше; `rootMargin`
  уже 800px, значит достаточно добавить именно скелетон.
- Сложность: M. Приоритет: P0.

#### 6. Обложки категорий режут блок посреди контента
- Где: `/blocks` и `/components`; кадр обложки `[data-part="cover"] .preview-frame`
  (`app/globals.css:679`, `padding:0`), масштаб `.block-thumbnail-scale`.
- Что не так: 1440/тёмная — обложка «Блог» показывает срез с обрезанным сверху
  заголовком «…Разборы решений, ошибок и переделок», «Вакансии» — середину списка,
  без начала секции. Кадр показывает произвольную вертикальную середину блока, а
  не его «лицо».
- Почему важно: обложка — единственное, по чему выбирают категорию глазами;
  обрезанный посреди строки контент выглядит как визуальный баг вёрстки.
- Что сделать: у обложки категории выравнивать масштабированный блок по верху
  (`align-items:flex-start` для `[data-part="cover"] .preview-frame` — сейчас общий
  `.preview-frame` центрирует, `app/globals.css:642`) и/или задавать
  `object-position: top` через `transform-origin: top center` (он уже такой у
  `.block-thumbnail-scale:807`, но кадр обложки центрирует контент по вертикали —
  конфликт). Проверить, что заголовок секции попадает в кадр.
- Сложность: M. Приоритет: P1.

- Что сделать: анимировать `grid-template-columns` нельзя кроссбраузерно, но можно

### Сценарии `/scenarios`

#### 15. Hydration mismatch на demo сценария (date-блок)
- Где: `/scenarios/photographer/demo` (и другие demo с формой брони); в консоли
  5 ошибок `hydrated but some attributes … didn't match`; источник — блок
  `contact-016` (`<input type="date" min="2026-09-16" style={{caret-color:transparent}}`).
- Что не так: `min` вычисляется от текущей даты, серверный и клиентский HTML
  расходятся — React логирует hydration-mismatch. Это registry-блок, его менять
  нельзя (правило проекта), но проявляется он на странице сайта `…/demo`.
- Почему важно: ошибки гидратации в консоли — сигнал нестабильности; на слабой
  машине частичный re-render добавляет к ожиданию. Для аудитора/разработчика это
  красный флаг на демо-витрине.
- Что сделать: НЕ править сам блок. На стороне рендера demo — обернуть проблемный
  контейнер `suppressHydrationWarning` или отрисовывать demo-iframe только на
  клиенте (`dynamic(..., { ssr:false })`) для сценариев с date/random. Уточнить у
  владельца: правка на стороне сайта допустима, блок остаётся нетронутым.
- Сложность: M. Приоритет: P1.

## Система моушена (предложение)

Опора — уже существующие токены `app/globals.css:67–70`:
`--motion-fast:140ms`, `--motion-base:220ms`, `--motion-slow:460ms`,
`--ease-out:cubic-bezier(0.16,1,0.3,1)`. Проблема не в их отсутствии, а в том, что
они применяются только в кабинете. Правила:

- **hover / focus**: `--motion-fast` + `--ease-out`. Свойства: `color`,
  `background-color`, `border-color`. Кольцо фокуса — без задержки.
- **press / active**: `transform: scale(0.97)` за `--motion-fast` (паттерн
  `.acc-press` уже есть, `app/globals.css:1242`).
- **hover карточек/подъём**: `translateY(-2px)` + `box-shadow` за `--motion-base`
  (паттерн `.acc-lift`).
- **появление контента / reveal**: `translateY(12–20px)+opacity` за `--motion-slow`.
- **переход страницы**: `acc-fade` 120/220ms (паттерн `.acc-page`).
- **скелетоны**: `.acc-skeleton` (shimmer 1.4s) под любым лениво-грузящимся кадром.
- **запрещено**: длительности-литералы (`duration-500/700`), вторая кривая
  `cubic-bezier(0.4,0,0.2,1)` на брендовых элементах, hover-цвет `#ff7a33` мимо
  `--shell-accent-deep`, mount-анимация при каждом ре-рендере (только на въезд/вставку).
- **всегда**: `@media (prefers-reduced-motion: reduce)` гасит transform/animation.

Фрагменты «было → стало»:

1. Кривая hover (находка 2)
```css
/* было: transition-colors → cubic-bezier(0.4,0,0.2,1) 0.15s */
.catalog-nav-item { transition-property: color, background-color, border-color; }
/* стало */
.ui-trans {
  transition: color var(--motion-fast) var(--ease-out),
              background-color var(--motion-fast) var(--ease-out),
              border-color var(--motion-fast) var(--ease-out);
}
```

2. Hover карточки каталога (находка 4)
```css
/* было */
.catalog-card { /* hover:border-shell-accent-line transition-colors */ }
/* стало */
.catalog-card {
  transition: transform var(--motion-base) var(--ease-out),
              border-color var(--motion-base) var(--ease-out),
              box-shadow var(--motion-base) var(--ease-out);
}
.catalog-card:hover { transform: translateY(-2px); box-shadow: var(--shell-shadow);
  border-color: var(--shell-accent-line); }
@media (prefers-reduced-motion: reduce){ .catalog-card:hover{ transform:none } }
```
