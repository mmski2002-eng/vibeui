# PIPELINE

Как item попадает в каталог. Это про конвейер, не про ассортимент: что и в
каком порядке делать — [ASSORTMENT.md](ASSORTMENT.md).

## Единственный ручной источник

Руками правятся только:

- `registry/<blocks|components>/<category>/registry.json` — metadata;
- `registry/<...>/<name>/<name>.tsx` — сам компонент;
- `registry/categories.ts` — когда заводится новая категория.

Всё остальное генерируется `npm run indexes` из этих файлов:

| файл                        | что в нём                                 |
| --------------------------- | ----------------------------------------- |
| `registry/sources.ts`       | список реестров и `kind` каждого          |
| `registry/previews.ts`      | карта slug → компонент для миниатюр и SSR |
| `registry/previews.lazy.ts` | ленивая карта для конфигуратора           |
| `registry.json` (корневой)  | `include[]` публикуемых реестров          |

Генератор — `scripts/build-indexes.mjs`. Он же проверяет инварианты, которые
раньше держались договорённостью: категория объявлена в `categories.ts`,
`categories[0]` item'а совпадает с реестром, `meta.ai.export` совпадает с
именем экспорта, выведенным из slug.

Зачем: раньше один item требовал правок в трёх параллельных индексах, а новая
категория — в пяти файлах. Это блокировало параллельную работу: два item'а
трогали одни и те же строки. Теперь папки item'ов независимы.

Порядок в каталоге: сначала блоки, потом компоненты; внутри типа — порядок
категорий из `registry/categories.ts`. Двигать item в каталоге = двигать его
категорию там.

## Новый item

```bash
npm run item -- <категория> [префикс]   # npm run item -- inputs input
```

Скаффолд заводит папку, `.tsx` по эталону (своя палитра `--vibeui-<name>-*`,
`<style href precedence>`, `prefers-reduced-motion`) и заготовку metadata с
`TODO`, после чего пересобирает индексы.

Заготовка намеренно **не проходит** `npm run meta:validate`: пока в metadata
остались `TODO`, сборка падает. Незаполненный item не уезжает на витрину.

Дальше по item'у:

1. написать компонент — визуальная идея, а не вариация цвета соседа;
2. заполнить metadata: `title`, `description`, `tags`, `ai.summary`,
   `ai.preserve` / `ai.adapt` (минимум по три пункта), `ai.notes`, `docs`;
3. для `kind: component` — `ai.usage` и `meta.controls`;
4. перевести: `meta.i18n.en` с тем же числом пунктов в списках;
5. `npm run meta:validate && npm run lint && npm run build`;
6. глазами: `/preview/<name>`, карточка в каталоге, страница item'а,
   светлая и тёмная подложка превью.

## Два правила, которые ловятся только сборкой

**Item обязан рендериться без пропсов.** Карта превью типизирована как
`Record<string, ComponentType>`, поэтому обязательный проп роняет `typecheck`.
Практический смысл тот же: миниатюра каталога рендерит компонент пустым, и
у него должно быть осмысленное состояние по умолчанию.

**Подложка превью объявляется в metadata.** `meta.preview.surface` (`"dark"`
или `"light"`) говорит, на каком фоне открывать карточку и страницу item'а.
Это не тема компонента — свою палитру он несёт сам и от контекста не
перекрашивается; поле лишь не даёт открыть светлое поле формы на тёмной
подложке. Пользователь всё равно может переключить.

## Что проверяет `meta:validate`

`scripts/validate-meta.mjs` знает про наши поля, которых нет в схеме shadcn.
Ошибки роняют сборку.

Metadata:

- остались `TODO` из скаффолда;
- нет `title`, `description` короче 40 символов, пустые `tags`;
- нет `ai.summary`, меньше трёх пунктов в `ai.preserve` / `ai.adapt`;
- нет `i18n.en`, в переводе не совпало число пунктов списка, не переведён
  `usage`, у контрола нет английского `label`, у текстового — `default`;
- контролы: дубли, неизвестный тип, `default` вне `options` или длиннее
  `maxLength`, цвет не `#rrggbb`;
- для `kind: component` — нет `ai.export`, нет ни `usage`, ни `controls`.

Исходник item'а:

- нет экспорта с ожидаемым именем (`button-001` → `Button001`);
- импорт откуда-либо кроме `react` — item обязан быть самодостаточным;
- классы темы проекта-хозяина (`bg-primary`, `text-muted-foreground` и т.п.):
  компонент несёт свою палитру, иначе после установки выглядит не так,
  как в preview;
- CSS-переменная без префикса `--vibeui-`;
- есть анимация, но нет правила `prefers-reduced-motion`.

Предупреждения не роняют сборку: связь контрола с `ai.adapt` ищется по тексту
и даёт ложные срабатывания.

## Параллельная работа

Item'ы независимы, кроме одного общего файла — `registry.json` своей
категории. Отсюда правило: **параллелить можно item'ы разных категорий**;
внутри одной категории — последовательно или с ручным разрешением конфликта
в конце (конфликт всегда один и тот же: два добавленных элемента `items[]`).

Индексы не коммитятся вручную: после слияния достаточно `npm run indexes`.

## Команды

```bash
npm run item -- <категория>   # скаффолд item'а
npm run indexes               # пересобрать индексы
npm run indexes:check         # упасть, если индексы устарели (CI)
npm run meta:validate         # metadata и исходники item'ов
npm run build                 # indexes + meta:validate + registry:build + next build
```
