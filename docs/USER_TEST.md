# USER_TEST — внешний тест сценария «выбрал → отдал ИИ → получил сайт»

Артефакт вехи из [ANALYSIS-2026-09-05.md](ANALYSIS-2026-09-05.md) (раздел 4,
пункт 6; раздел E). До этого файла тест существовал только как внутренняя
проверка разработчика на `localhost` (см. `docs/DELIVERY.md`, «Проверено
установкой») — не как воспроизводимый протокол для внешнего человека.

## Кто проводит

Внешний человек, который **не программист** и не участвовал в разработке
VibeUI. Он не должен знать, что такое registry, CLI или npm — только то, что
у него уже есть свой AI-агент (Claude Code, Cursor, любой с доступом в
интернет и в файлы проекта) и пустой/тестовый проект.

## Перед тестом — обязательная проверка прод-URL

`/c/<name>` должен отдавать ссылки на `vibeui.ru`, а не на `localhost`:
`REGISTRY_BASE_URL` вшивается в build (`docs/DEPLOY.md`), локальная сборка
этого не проверяет.

```bash
curl -s https://vibeui.ru/c/button-001 | head -20
```

Ожидается: команда установки и ссылки внутри инструкции ссылаются на
`vibeui.ru`, не на `localhost:3000`. Если нет — тест ниже проводить рано,
сначала почини прод-сборку.

## Сценарий (на трёх типах: block, component, animation)

Взять по одному item из каждого `kind`, например:
`hero-001` (block), `button-001` (component), `avatar` из `/animations` —
или любые другие, важно только, что все три типа охвачены.

Для каждого item:

1. Открыть страницу item'а на `vibeui.ru`, посмотреть preview.
2. Нажать «Copy for AI» на карточке или странице item'а.
3. В чате своего агента написать свою фразу с вставленной ссылкой, например:
   «размести такую кнопку в шапке: `https://vibeui.ru/c/button-001`».
4. Дать агенту выполнить: он должен сам открыть ссылку, прочитать
   инструкцию, выполнить команду установки и вставить компонент.
   **Не подсказывать** и не открывать ссылку самому.
5. Посмотреть результат в браузере рядом с preview на сайте.
6. Записать вердикт ниже.

## Результат (заполняется во время теста)

| # | Item | kind | Агент | Установил без правок вручную? | Совпало с preview? | Комментарий |
|---|------|------|-------|-------------------------------|---------------------|-------------|
| 1 |      | block |       |                                 |                     |             |
| 2 |      | component |   |                                 |                     |             |
| 3 |      | animation |   |                                 |                     |             |

«Совпало с preview» — честный вердикт по трём пунктам, не «примерно»:

- визуально то же (цвет, форма, spacing) — да/нет;
- состояния и анимация ведут себя так же — да/нет;
- агент не переписал/не пересоздал компонент своими словами — да/нет.

Если хотя бы один пункт «нет» — расхождение **обязательно** записывается в
колонку «Комментарий», а не сглаживается до общего «совпало». Провалы фиксировать
так же честно, как успехи — это весь смысл теста.

## Готово, когда

Все три item'а установлены, для каждого стоит вердикт и, если было
расхождение — его причина понятна (баг доставки, баг компонента, или агент
своевольничал вопреки инструкции).
